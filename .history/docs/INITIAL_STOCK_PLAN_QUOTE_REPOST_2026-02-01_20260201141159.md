# 初回ストック計画：引用リポスト戦略の最適解
## インプレッション・エンゲージメント期待値と Grok の責任範囲
**作成日**: 2026-02-01

---

## 1. 前提：戦略設計の数値（全体最適化の軸）

### 1.1 KPI（ゴール）

| 指標 | 目標値 | 備考 |
|------|--------|------|
| 無料版（Minimal）コンバージョン | **150+**/日 | 可能な限り最大化 |
| 有料版（Regular）コンバージョン | **50**/日 | 可能な限り最大化 |
| 無料側パイプライン（目安） | **750**/日 | 有料50をVSL2経由で賄う設計 |

### 1.2 逆算：インプレッション・引用リポスト数

| 項目 | 値 | 算出根拠 |
|------|-----|----------|
| 無料導線で必要なインプレッション/日 | **約 44 万** | 無料750想定、CTR 1%, CVR 20% |
| 有料直接用インプレッション/日 | **約 20 万** | 有料直接20想定 |
| **合計目標インプレッション/日** | **約 64 万** | 無料750＋有料50前提 |
| 1引用リポストあたりインプレッション（期待値） | **5,000** | インフルエンサー品質・アルゴに依存（後述） |
| **必要な引用リポスト数/日** | **約 128** | 64万 ÷ 5,000 |

### 1.3 エンゲージメントの期待値（在庫設計に使う）

| 指標 | 期待値 | 備考 |
|------|--------|------|
| 1引用リポストあたりインプレッション | **3,000〜7,000** | インフルエンサー品質で変動。中央値 5,000 で計画 |
| 1引用リポストあたりエンゲージメント率（いいね+RT+リプ） | **0.5〜2%** | アルゴ・タイミング・コピーに依存 |
| 1引用リポストあたりクリック率（CTA） | **0.5〜1.5%** | 無料/有料CTAで変動 |
| 無料CTA CVR（クリック→オプトイン） | **15〜25%** | VSL1品質に依存 |
| 有料CTA CVR（クリック→購入） | **5〜15%** | VSL3・プロモに依存 |

※ 在庫の質が高いほど、同じ投稿数でインプレッション・エンゲージメントは増える → **在庫の質＝広告単価（CPM/CPA）の改善**。

## 2. 初回ストックの最適解（数値で決定）

### 2.1 必要ストック数（Grok 打ち合わせに基づく）

Grok 自身の回答（2026-02-01）:
- **言語あたり 150〜200 username** で、1日 4〜5 回実行・1回1人採用 → 1日 20〜25 件/言語、7〜10 日ローテーション。
- **6言語合計 900〜1,200** username。

**初回ストックの最適解（こちらで決定）:**

| 言語 | 初回ストック目標（username数） | 根拠 |
|------|-------------------------------|------|
| en | **200** | 需要・Grok発見可能数（300〜500）とも最大。128投稿/日のうち多くを en で賄う想定。 |
| pt-br | **120** | 暗号採用強い。Grok 50〜90。余裕を持って 120 を目標。 |
| ko | **100** | 同様。Grok 50〜80。 |
| es | **80** | Grok 40〜70。 |
| ja | **80** | Grok 40〜70。 |
| ar | **40** | Grok 15〜35。候補が少ないため現実的な上限。 |
| **合計** | **620** | 初回は「全言語で最低限の質を満たす在庫」を確保。 |

※ 初回 620 で運用を開始し、2週間ごとの追加（Grok 推奨）で **900〜1,200** に増やしていく。

### 2.2 初回ストック時の期待値（数値）

| 項目 | 値 | 備考 |
|------|-----|------|
| 初回ストック総数（username） | **620** | 上表の合計。X API 検証後、実在する tweetId のみ採用するため、実ストック数は 620 より少なくなる可能性あり。 |
| 想定・引用リポスト可能数/日（初回） | **約 80〜100** | 620 人を複数回/日でローテーション。128 には届かないため、en 優先で配分。 |
| 想定・インプレッション/日（初回） | **約 40〜50 万** | 80〜100 投稿 × 5,000 imp。64万には届かないが、初回は「在庫の質」を固めるフェーズ。 |
| 目標・引用リポスト数/日（ストック増強後） | **128** | ストック 900〜1,200 で達成を目指す。 |
| 目標・インプレッション/日（ストック増強後） | **約 64 万** | 128 × 5,000。 |

### 2.3 ローテーション・負荷の数値

| 項目 | 値 | 備考 |
|------|-----|------|
| 同一インフルエンサーあたりの引用リポスト頻度 | **最大 4 回/日** | 既存実装 X_MAX_DAILY_POSTS_PER_INFLUENCER。 |
| 8時間クールダウン | インフルエンサーごと | スパム防止。 |
| ストック 620 で 1日 80 投稿する場合 | 約 **80 人/日** が 1 回以上使用 | 7〜8 日で一巡。 |
| ストック 1,200 で 1日 128 投稿する場合 | 約 **128 人/日** が 1 回以上使用 | 約 9〜10 日で一巡。 |

## 3. Grok の責任範囲（「Xアルゴリズム解析」「インフルエンサーリスト抽出」を信用して仕事させる）

Grok は **Xのアルゴリズムを解析できる** し **インフルエンサーリストも抽出できる** と自ら述べている。ここまで信用してついてきた以上、**責任を取ってもらう＝仕事させきる**。

### 3.1 Grok に依頼する仕事（役割）

| 依頼内容 | 期待する成果 | 備考 |
|----------|--------------|------|
| **username リストの提案（言語別）** | 上表の初回ストック目標数（en 200, pt-br 120, ko 100, es 80, ja 80, ar 40）にできるだけ近い件数で、**実在する X のスクリーン名** を返す。 | tweetId は依頼しない。username のみ。 |
| **実ツイートを渡したうえでのアルゴリズム・タイミング分析** | 引用リポストの「いつ・どのように」投稿するかの最適化。ランキング・エンゲージメント・タイミングの分析。 | 実データはこちらが X API で取得し、Grok に渡す。 |

### 3.2 初回ストック構築フロー（Grok 責任の具体化）

1. **Grok に依頼**  
   言語ごとに、上記目標数（en 200, pt-br 120, ko 100, es 80, ja 80, ar 40）に近い **username リスト** を出力させる。  
   - スクリプト: `scripts/ask-grok-list-size-and-discovery.js` の拡張、または言語別に「N 件の username を列挙せよ」と依頼するスクリプトを実行。
2. **こちらで検証**  
   X API で `username → user ID → 直近ツイート取得` を行い、**実在する tweetId** のみ採用。  
   - スクリプト: `scripts/experiment-grok-plus-xapi-one-influencer.js` の流れを言語別・一括で実行するパイプライン（Grok username 出力 → X API 検証 → KV 投入）。
3. **初回ストック 620 を目標に KV に投入**  
   検証通過分だけ `data/influencers-seed/` に書き、`rebuild-influencer-list-from-seed.js` で KV に投入。  
4. **運用後**  
   2週間ごとに Grok に追加候補を依頼し、同様に X API 検証 → ストック 900〜1,200 へ増強。

### 3.3 数値で見る Grok の「発見可能数」との整合

| 言語 | Grok 発見可能数（Grok 自己申告） | 初回ストック目標（本計画） | 整合 |
|------|----------------------------------|----------------------------|------|
| en | 300〜500 | 200 | 十分。Grok に 200 件依頼。 |
| pt-br | 50〜90 | 120 | やや上振れ。Grok の最大付近＋手動補完の余地。 |
| ko | 50〜80 | 100 | 同様。Grok 最大付近。 |
| es | 40〜70 | 80 | Grok 最大付近。 |
| ja | 40〜70 | 80 | 同様。 |
| ar | 15〜35 | 40 | Grok の上限付近。足りなければ手動補完。 |

→ **Grok には「各言語で目標数にできるだけ近い件数の username リスト」を出させる。** 足りない分は手動シードまたは Gemini 等で補う。

## 4. インプレッション・エンゲージメント期待値の一覧（全体戦略設計用）

| 指標 | 初回ストック時（620） | ストック増強後（900〜1,200） |
|------|------------------------|------------------------------|
| 引用リポスト数/日 | 約 80〜100 | **128**（目標） |
| インプレッション/日 | 約 40〜50 万 | **約 64 万**（目標） |
| 1投稿あたりインプレッション（期待値） | 5,000 | 5,000 |
| エンゲージメント率（期待値） | 0.5〜2% | 0.5〜2% |
| 無料コンバージョン/日（期待） | 約 75〜100 | **150+**（目標） |
| 有料コンバージョン/日（期待） | 約 25〜35 | **50**（目標） |

※ 無料・有料コンバージョンは、CTR・CVR の仮定（上記 1.3）に基づく逆算。実計測で更新すること。

## 5. まとめ

- **初回ストックの最適解**: 言語別で **en 200, pt-br 120, ko 100, es 80, ja 80, ar 40、合計 620**。  
- **数値**: インプレッション目標 64万/日、引用リポスト 128/日、1投稿あたり 5,000 imp 期待、エンゲージメント率 0.5〜2% を前提に全体戦略を設計。  
- **Grok**: 「Xアルゴリズム解析」「インフルエンサーリスト抽出」を信用し、**username リストの提案** と **実ツイートを渡したうえでのアルゴリズム・タイミング分析** を責任範囲として仕事させる。  
- **こちら**: username → user ID → tweets 取得 → 実在 tweetId の採用と KV 投入。初回 620 を目標にパイプラインを実行し、2週間ごとに 900〜1,200 へ増強する。
