## 2. 統合の考え方

- **アルゴリズム（Grok）**: 1,000〜2,000が有利。2,000近くまで伸ばすと滞在・深度は稼げるが、Geminiは2,000超を「満足離脱・説教感」のリスクと指摘。
- **心理・CVR（Gemini）**: 800〜1,200が「読み切り・行動」のピーク。1,000文字前後でツァイガルニクと信頼のバランスが取れる。
- **共通帯**: 両者が重なる **1,000〜1,200文字** が、アルゴリズムと心理の両方を満たすゾーン。

---

## 3. 結論 — 最適解（実装の指針）

### 推奨文字数

**軸: 1,000文字 / 許容帯: 800〜1,200文字**

- **テンプレ・生成の目標**: **1,000文字前後** で設計する。
- **許容範囲**: **800〜1,200文字** に収める（短くても800、長くても1,200を目安にトリム or 補足）。
- **上限の目安**: どうしても長くしたい場合は **1,500文字まで**。2,000を超えると心理リスク（満足離脱・説教感）が増えるため、ファネル用途では避ける。

### 実装への反映

| 観点                                     | 推奨                                                          |
| ---------------------------------------- | ------------------------------------------------------------- |
| 引用リポスト／長文ポストの**目標文字数** | 1,000文字                                                     |
| **最小**（短くしすぎない）               | 800文字以上                                                   |
| **最大**（長くしすぎない）               | 1,200文字（ゆるく運用するなら1,500まで）                      |
| 冒頭フック                               | 最初の200〜300文字で価値・フックを明示（Grok推奨）            |
| 構成                                     | 共感（痛み）→ 原因・新事実 → 解決の寸止め → CTA（Gemini推奨） |

既存の `HOOK_OPENING_MAX_LENGTH = 1000`（optimization.js）は、この「1,000文字を軸にした冒頭最適化」と整合しています。
