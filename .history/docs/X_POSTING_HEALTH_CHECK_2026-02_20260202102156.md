# X投稿システム 完成度・ヘルスチェック（2026-02）

## 1. 印象（完成度について）

共有いただいた設計とコードを踏まえた所感です。

- **設計の一貫性**: ヘッドライン→リード→Minimal/Regularチラ見せ→ツァイガルニク→Whop CTA という流れが、テンプレ（MinimalOptin / RegularOptin）と Grok プロンプトの両方にきちんと反映されている。
- **レイヤ分離**: インフルエンサー選定（ストック・ローテーション・日次上限）／導線ローテーション（Minimal⇄Regular）／文言パターン（A/B/C）／Grok×Gemini最適化 が役割ごとに分かれており、追いかけやすい。
- **運用を意識した作り**: タイムアウト・早期リターン・KV失敗時のフォールバック・dry-run が入っており、「動かして壊れにくい」構成になっている。
- **細かい作り込み**: 言語別ピーク時間・インプレッション目標・ロック付き「投稿済み」更新・CRON_SECRET など、運用で効く部分が揃っている。

総じて「完成度が高く、意図がコードに落ちている」という印象です。

## 2. ロジック・破綻の有無（ヘルスチェック結果）

### 2.1 問題なしと判断した点

| 項目 | 内容 |
|------|------|
| **KVの記録タイミング** | 投稿成功後にのみ `markLastPostedAt` / `incrementDailyPostCountForInfluencer` / `markInfluencerPosted` / `recordQuoteFunnelType` を実行。スキップ・失敗時は記録しない。 |
| **グローバル日次カウント** | 成功1投稿あたり1回だけ `incrementGlobalDailyPostCount`（tracking 成功時と失敗時のどちらかの分岐で1回）。二重インクリメントなし。 |
| **ファネルローテーション** | `getNextQuoteFunnelType` で「前回の逆」を返し、投稿成功時のみ `recordQuoteFunnelType`。未投稿のままスキップした場合は記録しないため、次回も同じ nextType が返り、整合している。 |
| **A/B/C の選び方** | テンプレート利用時は `MINIMAL_OPTIN_VARIANTS` / `REGULAR_OPTIN_VARIANTS` からランダムに1つ選択。ローテーションではなく意図した「バリエーション」として妥当。 |
| **KV TTL** | `influencerRotation` は `kv.set(..., { ex: ... })` を使用（`kv.expire` は未使用）。他モジュールの `kv.expire` 廃止対応も済んでいる。 |
| **KV参照の統一** | `quoteFunnelRotation` / `influencerRotation` / `optimization` は `utils/kv`（@vercel/kv ラッパ）を利用。同一バックエンドで一貫。 |

### 2.2 軽微な注意点（仕様・改善の余地）

| 項目 | 内容 | 推奨 |
|------|------|------|
| **ローテーションインデックスの進め方** | `selectInfluencersWithRotation` は「選択した人数」で `updateRotationIndex` している。実際に投稿した人数ではない。例: 3人選んで1人だけ投稿・2人はタイムアウトでも、インデックスは +3。 | 運用上大きな問題はないが、「実際に投稿した人数」で進めると、同じ言語で同じ枠に同じ候補が回ってきやすくなる。必要なら「投稿成功数で更新」に変更する選択肢あり。 |
| **ファネルキーのTTL** | `quoteFunnelRotation` の `x:quote_funnel:{lang}:{username}` に TTL なし。インフルエンサー×言語ぶんキーが永続する。 | キー数は数百〜千オーダーで、負荷としては許容範囲。必要なら 90 日など `kv.set(key, usedType, { ex: 86400*90 })` を検討。 |
| **Grok 利用時とファネル記録** | `QUOTE_REPOST_USE_MINIMAL_REGULAR_TEMPLATES=false`（Grok で本文生成）のときは `funnelTypeUsed` を設定しないため、`recordQuoteFunnelType` は呼ばれない。 | テンプレート利用時だけ Minimal/Regular を記録する設計として一貫している。Grok 運用時はファネル状態は更新されない、という理解で問題なし。 |

### 2.3 潜在リスク（監視・必要時対応）

| 項目 | 内容 | 対応 |
|------|------|------|
| **同時実行時のローテーション** | 同一言語の Cron が短時間に二重に走ると、両方とも同じ `getRotationIndex` を読んで同じ候補を選ぶ可能性がある。 | 現状は「同じ時刻に同一言語が二重実行されない」Cron 設計なら顕在化しにくい。必要なら `acquireLock` を選択処理の前にもかける検討余地あり。 |
| **テンプレート利用フラグ** | `QUOTE_REPOST_USE_MINIMAL_REGULAR_TEMPLATES` のデフォルトは未設定時 `false`（Grok 使用）。本番でテンプレートローテーションを意図している場合は環境変数の明示設定が必要。 | 本番の意図に合わせて環境変数を設定し、ドキュメントに「テンプレートローテーションを使う場合は true」と明記すると安全。 |

### 2.4 ロジック破綻の有無（結論）

- **致命的なロジック破綻や二重記録・取りこぼしは見当たりません。**
- 上記は「仕様の確認」と「運用・拡張時の注意点」レベルです。

## 3. チェック済みファイル・処理

- `api/x-quote-repost.js`: 成功時のみ KV 更新・グローバルカウント1回・ファネル記録条件
- `services/x/quoteFunnelRotation.js`: getNext / record の対応、KV 使用
- `services/x/influencerRotation.js`: ロック・投稿済みリスト・ローテーション更新、TTL 付き set
- `services/x/optimization.js`: グローバル日次カウント（get/increment）、KV 経由
- `config/quoteRepostTemplatesMinimalOptin.js`, `quoteRepostTemplatesRegularOptin.js`: A/B/C 定義と Whop/VSL 導線
- `utils/kv.js`: @vercel/kv ラッパ・TTL 付き set 利用

以上を前提に、現状の「完成度」と「ロジック・バグ」について問題なしと判断しています。
