# 投稿スケジュール vs X API レート制限（初速は加速が必要）

**作成日**: 2026-02-01  
**参照**: [X API Rate Limits](https://docs.x.com/x-api/fundamentals/rate-limits)（投稿は Manage posts の POST `/2/tweets`）

---

## 結論：**目いっぱい攻めていない（余裕あり）**

車・飛行機・船と同じで初速に加速が必要なら、**いまのスケジュールは X API の制限に対してかなり控えめ**です。レート制限まで振り切っていないので、**投稿頻度を上げる余地**があります。

---

## 1. X API の投稿まわり制限（公式）

| 種別                                               | 制限                          | 出典                                                                                  |
| -------------------------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------- |
| **POST /2/tweets**（通常ツイート・引用ポスト含む） | **Per User: 100 回/15分**     | [Rate limit tables - Manage posts](https://docs.x.com/x-api/fundamentals/rate-limits) |
| 同上                                               | **Per App: 10,000 回/24時間** | 同上                                                                                  |

- 15分あたり 100 なら、理論上 **1時間 400 投稿・24時間 9,600 投稿**（Per User）まで可能。
- アプリ単位では **24時間 10,000 投稿** まで。

---

## 2. いまの運用

| 項目                     | 値                                                                      | 備考                                                          |
| ------------------------ | ----------------------------------------------------------------------- | ------------------------------------------------------------- |
| Cron                     | 6言語 × **1回/時**（EN :00, ES :05, PT-BR :10, AR :15, JA :20, KO :25） | `vercel.json`                                                 |
| 1時間あたりの最大投稿数  | 各言語 1〜3 件/回 → **合計 約 10 件/時**                                | `config/influencerStrategy.js` の INFLUENCER_COUNT_BY_LANG 等 |
| 1日の目標投稿数          | **約 240 件/日**                                                        | 同上・ドキュメント                                            |
| コード上の日次上限       | **250 件/日**（`X_MAX_DAILY_POSTS`）                                    | `services/x/optimization.js`                                  |
| コード上の時間あたり上限 | **100 件/時**（`X_MAX_HOURLY_POSTS`）                                   | 同上                                                          |

---

## 3. 比較（「目いっぱい」かどうか）

| 制限の種類             | 上限              | 現在の運用 | 使用率（目安） |
| ---------------------- | ----------------- | ---------- | -------------- |
| X API（Per User）      | 100/15分 ≒ 400/時 | 約 10/時   | **約 2.5%**    |
| X API（Per User・24h） | 9,600/日          | 約 240/日  | **約 2.5%**    |
| X API（Per App・24h）  | 10,000/日         | 約 240/日  | **約 2.4%**    |
| 自前の日次上限         | 250/日            | 約 240/日  | 約 96%         |
| 自前の時間あたり上限   | 100/時            | 約 10/時   | **約 10%**     |

→ **X API 的には「目いっぱい」ではなく、かなり余裕がある**。  
→ 「初速で加速したい」なら、**投稿回数・頻度を増やしてまだ十分に収まる**。

---

## 4. 初速を上げるための選択肢（例）

以下はすべて X API の範囲内で検討可能です。

1. **Cron を「1時間1回」→「30分1回」に増やす**
   - 6言語 × 24h × 2 = **288 回/日**。
   - 1回あたりの投稿数が同じなら、**日次投稿数は約 2 倍**（約 480/日）まで増やせる。
   - 10,000/24h（Per App）の約 5% 程度。

2. **言語ごとの 1 回あたり投稿数（INFLUENCER_COUNT_BY_LANG）を増やす**
   - ストックと 8h クールダウン・日次上限と相談しつつ、1回あたり 2〜4 件などに増やす。
   - 時間あたり 10 件 → 20〜30 件にしても、100/時（自前）・400/時（API）のどちらにも余裕あり。

3. **自前の上限を API に少し寄せる**
   - `X_MAX_DAILY_POSTS` を 250 → 300〜400、`X_MAX_HOURLY_POSTS` を 100 → 50〜80 など、  
     スパム判定を避けつつ「初速」を強める調整が可能（AI 推奨 200–300/日はドキュメント参照）。

4. **ピーク時間だけ頻度を上げる**
   - UTC 0,1,20,21,22 などピーク時にだけ 30 分間隔にする、など部分的な強化。

---

## 5. 実装上の注意

- **429 (Rate limit exceeded)** を避けるため、  
  レスポンスヘッダー `x-rate-limit-remaining` / `x-rate-limit-reset` を確認し、  
  必要なら [Handling rate limits](https://docs.x.com/x-api/fundamentals/rate-limits#handling-rate-limits) のとおりリトライ・バックオフを入れると安全です。
- 投稿数だけ増やすとスパム判定リスクが上がるため、  
  **日次 200–300 前後を目安にしつつ、段階的に上げる**運用がおすすめです（`services/x/optimization.js` のコメントと一致）。
