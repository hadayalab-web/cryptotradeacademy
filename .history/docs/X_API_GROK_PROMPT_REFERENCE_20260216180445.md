# X API 公式仕様確認用 — Grok へのプロンプト

以下を Grok（または X API 公式リファレンス）に投げ、返答をこのファイルの「回答メモ」に追記して運用に活用する。

---

## プロンプト（コピペ用）

```
X API (Twitter API v2) の公式仕様について、以下の3点を教えてください。開発している Bot のパラメータ設計と障害対応のため、公式ドキュメント・ベストプラクティスに基づいた回答をお願いします。

1. **Rate limit（レート制限）**
   - **GET /2/tweets/search/recent** と **POST /2/tweets** について、アプリ／ユーザーあたりの制限（リクエスト数/時間単位など）を教えてください。
   - 1回の run で search/recent を「クエリ2本 × 1クエリあたり3ページ」で叩き、その後 POST /tweets で最大20件程度投稿する運用を想定しています。1日に such run を複数回（例: 9回）行う場合、レート制限に引っかからない目安や注意点はありますか。

2. **検索の時間範囲（start_time / end_time）**
   - search/recent で「直近15分」や「直近30分」のツイートを取得するとき、**start_time** と **end_time** の指定方法で、公式が推奨している書き方や制約（例: 最大何分前まで有効、UTC 指定の要否など）はありますか。
   - 検索の鮮度とヒット数を両立させるうえで、時間範囲のベストプラクティスがあれば教えてください。

3. **402 Payment Required**
   - 402 が返る主な条件（例: クレジット枯渇、プラン上限など）を教えてください。
   - 402 発生後、解消までの目安時間や、再試行の推奨（例: 一定時間あけてから再送する等）はありますか。開発側で「402 が出たら一定時間はリクエストを控える」といった運用をしたい場合の目安を知りたいです。

引用元（公式ドキュメントの URL や該当セクション）があれば、あわせて教えてください。
```
