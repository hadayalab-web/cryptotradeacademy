# 数十万〜数百万インプレッション時の「成約ゼロ」回避

## 目的

インプレッションが毎日数十万〜数百万規模になっても、**成約ゼロ**にならないようにするための監視・チェック・改善の指針。

---

## 1. 成約までの流れ（押さえておくこと）

```
X投稿（引用リポスト / 無料版 / 有料直接）
  → インプレッション
  → クリック（リンク・CTA）
  → Whopページ / Telegram Deep Link
  → サインアップ or チェックアウト
  → 成約（Whop Webhookで検知）
```

**ポイント**: インプレッションだけ増えて「クリック→Whop→成約」がゼロだと、悲しい。  
**対策**: インプレッション増加の**前**から「クリック・Whop・成約」を測れるようにし、**先行指標**で早期に問題に気づく。

---

## 2. 監視すべき指標（優先度順）

| 優先度 | 指標                                    | 見方                                   | ゼロだったら                                   |
| ------ | --------------------------------------- | -------------------------------------- | ---------------------------------------------- |
| P0     | **成約数**（Whop Webhook）              | Whopダッシュボード / Webhookログ       | ファネル・リンク・CTAを即確認                  |
| P0     | **Whopページビュー**（商品ページ）      | Whop Analytics                         | リンクが壊れている or 投稿に載っていない可能性 |
| P1     | **Telegram Bot 登録**（/start）         | Bot利用数・Deep Link起動               | 無料→有料の入口が動いているか                  |
| P1     | **X投稿のクリック数**（リンククリック） | X API メトリクス（url_link_clicks 等） | CTA・リンク配置の見直し                        |
| P2     | **インプレッション**                    | 既存のXメトリクス                      | 伸びていればアルゴリズムは届いている           |

**重要**: 「インプレッションはあるがクリック・Whop・成約がゼロ」が続いたら、**リンク・CTA・ランディング**側の不具合を疑う。

---

## 3. 技術チェック（定期的に）

以下は**コード・設定**側で「成約ゼロ」の原因になりうる箇所。監視スケジュールに組み込むとよい。

### 3.1 Whopリンクが生きているか

- **Regular（有料）**: `services/telegram/whop-links.js` の `getWhopProductUrl(lang)`
  - 各言語のデフォルトURL / 環境変数（`WHOP_PRODUCT_URL_*`）が正しいか
- **Minimal（無料）**: `getMinimalVersionCheckoutUrl(lang)`
  - 同上、Minimal用URL・環境変数
- **プロモコード**: `getPromoCode()`（例: defend50）がWhop側で有効か

### 3.2 投稿にリンクが含まれているか

- **引用リポスト**: `api/x-quote-repost.js` で `getWhopProductUrl(lang)` / `getPromoCode()` を組み合わせたリンクが本文に入っているか
- **無料版投稿**: `api/x-post-minimal-version.js` の Deep Link + Whop有料リンク
- **有料直接**: `api/x-post-regular-direct.js` の Whop URL + プロモ
- **無料ブリーフ**: `api/x-post-free-report.js` の「UPGRADE」CTA + Whop URL

（テンプレート変更や条件分岐でリンクが抜けないよう、デプロイ後のスポットチェック推奨。）

### 3.3 Whop Webhook（成約検知）

- **api/whop-webhook.js**: 成約イベントを受信してKV等に記録
- 本番では `WHOP_WEBHOOK_SECRET` が設定され、署名検証が通っているか
- Whopダッシュボードで Webhook URL が正しく登録され、配信エラーが出ていないか

### 3.4 ファネル疎通の一括確認

```bash
node scripts/verify-funnel-health.js
```

- Telegram Deep Link / Whop Link / プロモ付きURL が正しく生成されるか
- 定期的（例: 週1）実行し、リンク切れや環境変数ミスを早期検知

---

## 4. 先行指標で「成約ゼロ」を防ぐ

- **インプレッションだけ増えて、クリック・Whop・成約がずっとゼロ**  
  → まず「クリック」と「Whopページビュー」を確認。  
  どちらもゼロなら、**リンクの有無・誤り・表示位置**を疑う。
- **クリックはあるがWhopがゼロ**  
  → リンク先URLの誤り・リダイレクト不備・Whop側の障害を疑う。
- **Whopはあるが成約ゼロ**  
  → 価格・プロモ・LP・支払いフロー・オファーの見直し（コードよりプロダクト側）。

「成約ゼロ」に気づいた時点で、上記のどれで止まっているかを切り分けると、修正が早い。

## 6. 運用の一言

数十万〜数百万インプレッションは「届いている」証拠。  
そこで**成約ゼロ**にしないためには、  
「インプレッション → クリック → Whop → 成約」の**どこで止まっているか**を数値で見て、  
リンク・CTA・Webhook・オファーを**継続的にチェック・改善**することが重要。

このドキュメントは、そのチェックリストとして使ってください。
