# アフィリエイト戦略：X DM リクルート → FirstPromoter 登録 → Whop 販売

**方針**: 従来の「仕手Bot寄生リプライ＋オーガニック集客」から、**X 上で EN/ES/PT/AR/KO/JA の高品質アフィリエイターを DM でスカウトし、FirstPromoter に順次登録してもらい、Whop プロダクトを販売してもらう**戦略に大幅アップデートする。

**DM リクルートの前提**
- 魅力的な案件を探しているアフィリエイターは DM を欲しがっている。
- 未フォロー・未会話で DM を拒否するアフィリエイターは無視してよい（403 は NG リストで再送しない）。
- Trap Defence をアフィ報酬 50% で売りたいアフィリエイターは世の中にゴロゴロいるはず。届く相手を増やせばよい。

**スクリーニングの現状認識**
- **現状のスクリーニングは甘い**。403 になる候補を減らすには「DM が届きやすい相手」を優先して探す必要がある。
- やることは **DM が届きやすい相手を探す** こと。403 データ（NG リストに保存した score / lang / breakdown）を分析し、届きやすい属性・条件を強めてスクリーニングを強化する。

※ 表記: **FirstPromoter**（アフィリエイト管理 SaaS）。FirstPrompter との表記ゆれがある場合は本ドキュメントでは FirstPromoter に統一する。

## 1. 戦略の全体像

| フェーズ | 内容 | 担当・ツール |
|----------|------|----------------|
| **1. 発掘** | X 上で 6 言語圏（EN/ES/PT/AR/KO/JA）の高品質アフィリエイター候補を検索・リスト化 | X Search API / 手動リスト / 外部 MCP |
| **2. スカウト** | 候補に X DM でスカウトメッセージを送り、FirstPromoter 登録への誘導 | X DM API（POST /2/dm_conversations 等） |
| **3. 登録** | 承諾した候補を FirstPromoter に順次登録（招待リンク or 手動登録） | FirstPromoter ダッシュボード / API |
| **4. 販売** | アフィリエイターが Trap Defence BTC（Whop）を紹介し、報酬を得る | Whop + FirstPromoter 連携（または Whop ネイティブアフィリエイト） |

**北極星**: 高品質アフィリエイター数を増やし、彼らのリーチで Whop 成約・LTV を拡大する。

**成功の前提**: **良質なアフィリエイターさえ集められれば、売上を獲得できる**。商材（DEFEND50・1 日トライアル・50% 報酬・継続収益）は訴求力があり、あとは「スカウト → 登録 → 紹介」のパイプラインで質の高いプロモーターを増やすことが売上拡大の鍵になる。

**保存・進捗管理**: Notion は利用しない。候補リスト・DM 送信履歴・登録状況は Supabase または Vercel KV で管理する。

## 3. 「高品質アフィリエイター」の定義（スカウト基準）

- **フォロワー数・エンゲージメント**: 一定以上のリーチと ER（例: フォロワー 3K〜50K、ER 2% 以上など）。スパム・Bot っぽいアカは除外。
- **コンテンツの一貫性**: クリプト・トレード・マーケット・金融系で一貫して発信している。
- **言語**: メイン投稿が対象言語（EN/ES/PT/AR/KO/JA）のいずれか。
- **商業的許容**: プロモ・紹介・有料コンテンツを既に扱っている、または許容しそうなトーン。
- **重複排除**: 既に FirstPromoter 登録済み・既に DM 送付済みは除外。

### 3.1 「FirstPromoter や Whop に免疫がある」候補を優先したい場合

**意味**: まだ FirstPromoter や Whop をあまり使っていない（＝他ブランドのアフィリエイトで飽和していない）アフィリエイターを見つけ、スカウトの反応率・登録率を上げたい、という想定。

| 対象 | 外から分かるか | できること |
|------|----------------|------------|
| **FirstPromoter** | ❌ **分からない** | 他社の FirstPromoter に登録しているかは公開情報ではない。**当方でできるのは「当方に既に招待済み・登録済み」の重複排除のみ**（自前 DB で管理）。 |
| **Whop** | ⚠️ **推測なら可能** | プロフィールや直近投稿に **whop.com / "whop" / "Whop affiliate"** が頻出するアカウントは、すでに Whop 系アフィリエイトをしている可能性が高い。**それらを除外または下げて優先度をつける**ことで、「Whop に免疫がある（まだあまり使っていない）」候補を相対的に多く拾える。 |

**実装の方向性（Whop 免疫の簡易フィルタ）**

- 候補の **user オブジェクト**（`description`）と、取得済みの **ツイート本文** に対して、
  - `whop.com` や `whop`（大文字小文字無視）の出現回数や有無をチェックする。
- **スコア化**: Whop 言及が少ないほど「Whop に免疫がある」としてスコアを高くする。または、言及が多すぎる（例: 直近テキストに 2 回以上）場合は候補から外す／優先度を下げる。
- X API で取得できる範囲（検索結果の tweet + expansions の user）だけでも、**投稿テキスト＋プロフィール**で一定のフィルタは可能。必要なら「候補の直近ツイートをさらに取得」して Whop 言及頻度を数えてもよい（API コストは増える）。

※ FirstPromoter はサービス名が投稿に出ることは少ないため、同様の「言及で検出」は現実的ではない。**FirstPromoter については「当方の招待済みリストで重複排除」のみ**とする。

### 3.2 望ましい属性：意欲・活動的・実績・誠実（どこまで求められるか）

**理想**: 稼ぐ意欲が旺盛で、活動的で、実績があり、ルールやモラルを順守する誠実なアフィリエイターを集めたい。ただしすべてを事前に「見抜く」ことは難しく、**観測できる範囲でスコア化し、登録後は規約・モニタリングで補う**形が現実的。

| 属性 | スカウト前にどこまで分かるか | 現実的な扱い |
|------|------------------------------|--------------|
| **稼ぐ意欲が旺盛** | ⚠️ **推測まで** | プロモ・有料案内・紹介リンク・「DMで」等の文言を既に使っているアカウントは、収益化への意欲が高いと**推測**できる。テキストやプロフィールから「商業的許容」スコアを付与することは可能。本心の「意欲」は DM や登録後の反応でしか分からない。 |
| **活動的** | ✅ **ある程度まで** | 投稿頻度・直近の投稿有無は X API で取得できる。検索窓でヒットしている＝その窓で投稿した＝活動の一証拠。フォロワー数・tweet_count（プロフィール）も活動量の代理指標になる。**活動的かどうかは、観測可能な範囲ではかなり見える**。 |
| **実績あり** | ⚠️ **代理指標のみ** | フォロワー数・エンゲージメント率・「〇万フォロワー」等のプロフィール表記は「実績の代理」。本当の成約数・売上は FirstPromoter/Whop 側でしか分からず、**登録後に当方プログラムでの実績**として積み上がる。スカウト段階では「リーチとエンゲージメント」で実績の**可能性**を推測するにとどまる。 |
| **ルール・モラル順守／誠実** | ❌ **事前にはほぼ分からない** | 虚偽表記・規約違反・スパムっぽい投稿は**テキストヒューリスティック**で一部除外できる（既存のブロックワード・スパムパターン）。ただし「誠実かどうか」は、**登録後の振る舞い**（不正クリック・規約違反・苦情）で初めて判明する部分が大きい。**規約明示・モニタリング・問題発生時の対応**で事後的に担保する設計が現実的。 |

**まとめ**

- **意欲・活動的・実績**: スカウト前に **活動量・フォロワー・エンゲージメント・商業的トーン** でスコア化し、優先度をつけることはできる。完全な保証ではないが「望ましそうな候補」を**相対的に**多く選ぶことは可能。
- **誠実・ルール順守**: 事前に確実に見分けるのは難しい。**規約・禁止事項を明文化し、FirstPromoter/Whop 側の不正検知と連携し、問題があれば招待停止やペイアウト保留**で対応する運用で補う。

### 3.4 「隠された敵」×「島への招待」ハイブリッド戦略（最適化済み）

全体のスカウト・スクリーニング・DM・登録後アセットを統一ナラティブで最適化している。

| 要素 | 内容 |
|------|------|
| **隠された敵** | 本当の敵はトラフィックではなく、壊れた商品（煽り商材）。低 CVR・高チャーン・信頼崩れの原因 |
| **島への招待** | Hell Island（煽り→損→信頼崩れ）から Heaven Island（盾として Trap Defence）への転換を提案 |
| **スクリーニング** | 煽り/hype 系キーワードを含む投稿の候補にボーナス加点。痛みを抱える候補を優先（`affiliateRecruitScoring.js`） |
| **DM** | variant 2（script）を 70% 優先。Hell Island→Heaven Island の全文を送る |
| **検索** | affiliate, referral, signals, アフィリエイト, シグナル 等を追加し、転換ニーズの高い候補を拾う |
| **AFFILIATE_EXPECTATIONS** | 各言語冒頭に「隠された敵／天国の島」文脈を挿入し、一貫したストーリーを維持 |

### 3.5 DM 受信への抵抗感（前提）

**前提**: スカウト対象は「アフィリエイト案件を公募している」「紹介・プロモを既にやっている」層であることが多い。彼らは**アフィ案件そのものに興味・許容がある**ため、**DM でアフィリエイト案内を受け取ることへの抵抗は、一般ユーザーより相対的に低い**とみなしてよい。

- 検索条件で「アフィリエイト募集」「affiliate program」「紹介で稼ぐ」等にヒットするアカウントは、すでに**商業的・紹介系のコミュニケーションを前提**にしている。
- そのため、DM 文案は「一方的な営業」より**案件の概要・メリット・次の一歩**を簡潔に伝えるトーンで十分であり、「DM を送ること自体が失礼」と過度に萎縮する必要はない。ただし **スパム・押し売り・規約違反** は避ける。

## 4. X DM リクルートフロー

### 4.1 技術前提

- **X API**: DM 送信は「DM インタラクション: 作成」で課金（例: $0.015/リクエスト）。レート制限・スパム判定を避けるため、**送信頻度・文面のバリエーション・フォローアップ間隔**を設計する。
- **送信前**: 相手が DM を受け取れる設定か（公開アカウントかつ DM 開放）を確認できる範囲でチェック。
- **送信後**: 開封・返信を追跡する場合は X Webhook（direct_message_events）の利用を検討。

### 4.2 スカウトメッセージの設計（言語別）

- **短く・価値提案を明確に**: Trap Defence BTC の紹介パートナー募集であること、報酬（例: 売上の 50% 等）を一言で伝える。
- **FirstPromoter 登録リンク（または Whop アフィリエイトページ）を記載**: クリックで登録→リンク取得までをワンストップに。
- **言語別テンプレ**: EN/ES/PT/AR/KO/JA それぞれで 1〜2 パターン用意し、パーソナライズ（ハンドル名・最近の投稿への言及）を任意で追加。

### 4.3 送信ペースとリスク回避

- **1 日あたりの DM 本数**: スパム判定を避けるため、初速は少なめ（例: 5〜15 本/日）から開始し、問題なければ段階的に増やす。
- **間隔**: 連続送信を避け、ランダム遅延（例: 5〜15 分）を入れる。
- **バリエーション**: テンプレを 3〜5 種類ローテーションし、同一文面の連続送信を避ける。

## 5. FirstPromoter 登録フロー

- **招待方式**: FirstPromoter の「招待リンク」を DM に含め、クリックでサインアップしてもらう。
- **Whop 連携**: FirstPromoter は Stripe/Paddle/Chargebee 等と連携が一般的。Whop 単体では API 連携が別途必要になるため、**Whop ネイティブのアフィリエイト機能**と FirstPromoter の役割（登録者管理・ランキング・ペイアウト）を整理する必要がある。
  - **Option A**: Whop アフィリエイトのみ使い、FirstPromoter は「登録者リスト・DM 送信対象の管理」に使う。
  - **Option B**: FirstPromoter のトラッキングリンク経由で Whop に誘導し、コンバージョンを FirstPromoter で計測（Whop API または Webhook で売上を FirstPromoter に通知する仕組みが必要）。
- **順次登録**: 承諾した人から順に FirstPromoter 上でプロモーターとして登録し、アフィリエイトリンク・プロモコードを付与する。

## 6. Whop プロダクト販売

- **商品**: Trap Defence BTC（Regular Briefing 等）。既存の Whop 商品 ID・プラン・プロモコードをそのまま利用。※ **DEFEND50** はアフィリ経由でしか付与されない特別なプロモコード（一般公開・他チャネルでの配布はしない）。
- **アフィリエイト報酬**: 既存方針（例: 50% 等）を維持し、FirstPromoter または Whop 側で設定。
- **言語別ランディング**: EN/ES/PT/AR/KO/JA 向けの説明・VSL・CTA を既存資産で揃え、アフィリエイターに同じリンクを渡すか、言語パラメータ付きで渡す。

### 6.1 商材の訴求ポイント（両面）— DM・ランディングで使う

[Trap Defence BTC｜Regular (EN)](https://whop.com/trapdefence/btc-regular-en/) を代表とする CryptoTrade Academy 商材は、**購入者**と**アフィリエイター**の両方に明確なメリットがあり、スカウト DM や紹介用ランディングのコンテンツとして使いやすい。

| 対象 | 訴求内容 | 備考 |
|------|----------|------|
| **ユーザー側（購入者）** | **初回プロモコード DEFEND50** で 50% オフ。**1 日無料トライアル**付き（月額プラン）。プラン例: $99/月、$237/3 ヶ月（20% off）、$845/年（29% off）。 | 商品ページ・メール・アフィリエイターが紹介する際の「顧客向けフック」として使う。 |
| **アフィリエイター側** | **アフィリエイト報酬 50%**。**サブスク継続で永続的な収益**（紹介した顧客が継続課金する限り報酬が続く）。 | DM リクルート文案（`config/affiliateRecruitDmTemplates.js`）で「50% rev share, recurring」等として既に反映。 |

DM 文案やランディングでは「紹介する側には 50%・継続報酬」「紹介される側には DEFEND50・1 日トライアル」の両方を短く含めると、魅力的なコンテンツとして伝わる。
