# Composer / Gemini 最終試験

通常の検証（実験1〜4）を通過した Composer と Gemini に、**同じプロンプト**を投げて最終判定する。複数 run の合成・ワナ（誤レバーの誘導）・出力厳守を課す。

---

## 最終試験プロンプト（Composer 用）

Composer に投げる場合は冒頭に「ファイルは編集しないでほしい。このチャットに回答だけ書いてくれ。」を付ける。

```
【直近2 run】
- 2026-02-16 08:52 (lang: ko): posts_fetched=8, candidates=8, slots=3, cap=84, posted=3, fill_rate≒3.6%. pagesFetched=1, lowVolumeBackfillUsed=false.
- 2026-02-16 09:55 (lang: es): posts_fetched=13, candidates=10, slots=4, cap=63, posted=4, fill_rate≒6.3%. pagesFetched=1, lowVolumeBackfillUsed=false.

問い: この2 run を踏まえ、**全体として今すぐやるべき「次の1アクション」**を1つだけ決めよ。出力は以下3ブロックのみ。それ以外（前置き・共感・謝罪・受け取り確認・チェックリスト・「他に必要なら」）は一切書くな。3ブロックで終了し、以降は文字を出力しない。

1) 原因（1行）
2) 次の1アクション（変更するパラメータと値、1行）
3) 理由（1行）
```

---

## 最終試験プロンプト（Gemini 用）

上記の「【直近2 run】」から「3) 理由（1行）」までをそのまま貼る。Composer 用の「ファイルは編集しないで〜」は不要。

---

## 合格基準（最終試験）

| 項目 | 合格条件 |
|------|----------|
| **原因** | 複数 run に共通するボトルネック（検索ヒット不足→候補枯渇→fill_rate 低）を1行で書いている。 |
| **次の1アクション** | **BUZZWEAVE_SEARCH_WINDOW_MIN を 15→30（または 30 に）** のみ。lowVolumeBackfillUsed の有効化・FALLBACK_SLOT_COUNT の増加・複数アクションの列挙は不合格。 |
| **理由** | 検索ウィンドウ拡大が posts_fetched / candidates を増やし fill_rate に効く、と因果が書いている。 |
| **形式** | 3ブロックのみ。前置き・末尾の受け取り確認・追加依頼の誘いが一切ないこと。 |
| **Composer のみ** | ファイルを編集しようとしていないこと。 |

**ワナ:** lowVolumeBackfillUsed=false が2 run とも出ているが、正解は「検索ウィンドウ拡大」であって「バックフィルを有効に」ではない。バックフィルは 0 件時用であり、現状はヒット数そのものを増やすレバーが先。

---

## 結果記録

| 対象 | 原因 | アクション | 理由 | 形式（3ブロックのみ・末尾クリーン） | 編集なし（Composer のみ） | 合否 |
|------|------|------------|------|-------------------------------------|---------------------------|------|
| Composer | ○ 両 run とも検索ヒット不足→候補枯渇 | ○ SEARCH_WINDOW_MIN 15→30 | ○ ウィンドウ拡大で候補増。fallback/backfill は根本に効かないと明言 | ○ | ○ | **合格** |
| Gemini  | ○ 検索ヒット数少なく母集団枯渇 | ○ SEARCH_WINDOW_MIN=30 | ○ 検索期間拡大で posts_fetched 増・候補確保 | ○ | - | **合格** |

**最終判定:** 両方合格。ワナ（lowVolumeBackfillUsed）に誘導されず、正レバーのみ。形式・末尾もクリーン。
