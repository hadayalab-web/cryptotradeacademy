# BuzzWeave 目標投稿数の根拠

Copilot 案の「2〜4 run/日」は根拠がなく、かつ **6言語×4導線＝24セル** を考えると明らかに少ない。  
ここでは **「言語・導線カバー」を前提にした目標 run 数** と **上限の根拠** を定める。

---

## 1. 前提（変えない）

- **1 run = 1 スレッド**（main 1本 + 自リプ 2本 = 最大 3 ツイート）
- **run 間隔は最低 3 時間**（shadowban 回避のため厳守）
- **X API への write** は buzzweave-run 経由のみ

---

## 2. 「6言語×4導線」を踏まえた必要 run 数

- **6 言語圏**: en, es, pt, ja, ko, ar
- **1 言語あたり 4 種類の導線**: vidalytics_leadmagnet / vidalytics_regular / whop_minimal / whop_regular 等
- **24 セル** を時間をかけて回す前提

**「少なすぎる」の根拠**:  
- 1 日 3〜5 run だと、6 言語に均すと **1 言語あたり 0.5〜0.8 run/日** 程度にしかならない
- 各言語で 4 導線の KPI を取るには、**最低でも 1 言語あたり 1 run/日** は欲しい → **6 run/日が最低ライン**
- 市場が荒い日は言語・導線のローテを多めに回す → **8 run/日** まで許容する設計にする

---

## 3. 根拠となる制約

### 3.0 2026年1月の X / X API 仕様更新（制限緩和）※要活用

- **確認できている範囲では**、2026年1月に X および X API の仕様が大幅アップデートされ、**同時に制限が大きく緩和されている**。
- 旧来の「24h あたり 50 ツイート」などの厳しい上限は、この更新で見直されている可能性が高い。
- **方針**: この緩和は **狙っていくべき**。デフォルト 6/7/8 run/日は保守的な起点として維持しつつ、実績（200〜300 投稿/日でペナルティなし）と合わせ、**run 数・間隔の上限を段階的に引き上げて積極運用する**ことを推奨する。

### 3.1 X API 制限

- **2025年以前**: Post limits（User Context）24h あたり **50 tweets** が一般的な上限だった。
- **2026年1月以降**: 仕様更新に伴い **制限が大幅に緩和**（詳細は公式ドキュメントで要確認）。上記 3.0 のとおり、緩和を活かした増量運用を狙う。
- 1 run = 最大 3 ツイート。緩和後は **8 run/日（24 ツイート）は十分余裕**。さらに run 数増やし・間隔短縮（例: 2h）も検討余地あり。

### 3.2 3h 間隔の物理上限

- 24h ÷ 3h = **最大 8 窓**
- なので **1 日の run 数は最大 8**（これ以上は間隔を空けられない）

### 3.3 エンゲージメントの質

- 8 スレッド/日までなら、3h 空けで「過剰投稿」になりにくい
- 6 言語を 1 日で 1 周（6 run）＋ 余力 2 run で、言語・導線のバランスを取る

---

## 4. 目標 run 数（根拠付き）

| 観点 | 値 |
|------|-----|
| 6言語カバー | **最低 6 run/日**（1 言語あたり 1 本） |
| 3h 窓の上限 | **最大 8 run/日** |
| API 余裕 | 8 run × 3 = 24 tweets < 50 ✅ |

**結論**:  
- **low（静穏）**: **6** run/日（18 ツイート）— 6 言語を 1 周  
- **medium**: **7** run/日（21 ツイート）— 1 言語だけ 2 本  
- **high（荒い）**: **8** run/日（24 ツイート）— 3h 窓いっぱい、言語・導線ローテ最大化  

これで「6言語×4導線を考えても少なくない」水準にする。

---

## 5. 環境変数での上書き

| 変数 | 説明 | デフォルト |
|------|------|------------|
| `BUZZWEAVE_DAILY_RUN_LOW` | ボラティリティ low の日の run 数 | **6** |
| `BUZZWEAVE_DAILY_RUN_MEDIUM` | ボラティリティ medium の日 | **7** |
| `BUZZWEAVE_DAILY_RUN_HIGH` | ボラティリティ high の日 | **8** |
| `BUZZWEAVE_MIN_RUN_INTERVAL_HOURS` | run 間隔（時間） | 3 |

---

## 6. 実運用での検証（2025）

**実績**: 6 言語展開後、**1 日 200〜300 投稿 × 1 週間継続**で、ペナルティ・シャドバン・レート制限は発生しなかった。

- この水準は、現行のデフォルト（6/7/8 run/日 ≒ 18〜24 ツイート/日）よりかなり多い。
- したがって **現在の 6/7/8 は保守的な設定** であり、必要に応じて `BUZZWEAVE_DAILY_RUN_*` を引き上げる余地がある。
- 200〜300/日まで増やす場合は、run 間隔を 2h などに短縮（`BUZZWEAVE_MIN_RUN_INTERVAL_HOURS=2`）するか、1 run あたりの投稿本数が増えない前提で run 数を増やす設計にする必要がある。

---

## 7. まとめ

- **6 言語 × 4 導線** を前提にすると、1 日 3〜5 run は明らかに少ない。
- **最低 6 run/日**（1 言語 1 本）、**最大 8 run/日**（3h 窓の上限）に引き上げ、根拠を「言語・導線カバー」「API・間隔の上限」に揃えた。
- **実運用で 200〜300 投稿/日 × 1 週間でペナルティなし** の実績があるため、デフォルトはあえて保守的にし、必要なら env で増やせるようにしている。
- **2026年1月に X / X API の制限が大幅緩和**されているため、**この緩和は狙っていくべき**。run 数・間隔の上限を段階的に見直し、積極運用を推奨する。
