# リクルートDM戦略 — 最適案まとめ

## 前提の整理

- **Read**（読み取り）= 検索条件数（クエリ本数）または取得リソース数。投稿/ユーザー読み取りで課金（$0.005–0.010/リソース）。
- **DM Interaction Create** = 送信成功 1 通 = $0.015/リクエスト。**403 はカウント・課金されない**。
- **目標**: Read を抑え、Create を伸ばす → **コスパ最大化**。

---

## 最適案（5本柱）

### 1. ターゲットは「すでにアフィリエイターとして活動している人」だけに絞る

- 検索・スコアとも「link in bio / referral link / whop / 紹介リンク」等の**活動シグナル**で絞る。
- **「DM募集中」は条件にしない**（XのDM設定と一致せず、403 が多く、候補数も減るため）。

### 2. Read は 1 に抑える（1 言語 1 クエリ）

- 全キーワードを 1 本の OR クエリにまとめ、**検索条件数 = 1** にする（`AFFILIATE_RECRUIT_SINGLE_QUERY` デフォルト有効）。
- 同じ Read コストで、**ページ数だけ増やして**候補を確保（例: 8 ページ × 50 = 400 ツイート → ユニーク作者が候補プール）。

### 3. 解像度の高いスクリーニングは「検索の後」でかける

- Read 1 でも、**スコアリング（ACTIVE_AFFILIATE / BIO / 除外条件）** で候補を厳選する。検索は広く拾い、スクリーニングで解像度を上げる。

### 4. Create 10 まで 403 を交わして到達する

- 送信目標を **10 成功**（`EN_RECRUIT_BATCH_SIZE=10`）。403 なら次候補へ進み、**成功 10 件になるまで試行**する。
- 候補プールを多めに取っておけば、403 が多くても Create 10 に届きやすい。

### 5. 403 は追いかけない

- 403 になった author_id は **90 日間再送しない**（dm_ng）。案件募集中なのに DM 拒否 = ターゲットではない、と割り切る。

---

## 運用イメージ

| 指標 | 狙い |
|------|------|
| Read | 1（1 クエリ・多ページ） |
| 候補数 | 数十〜100+（1 クエリ × 8 ページ等） |
| 試行 | 優先度順に送信、403 はスキップ |
| Create | 10/ラン（EN スロット） |
| 403 | 課金されない・追いかけない |

---

## 変更済み・設定済みのポイント

- 検索: 1 言語 1 クエリ（単一クエリ）、DM募集中キーワード廃止。
- スコア: ACTIVE_AFFILIATE 中心、DM募集中系キーワード廃止。
- ページ数: デフォルト 8（`SEARCH_PAGES_PER_BUCKET`）。
- EN バッチ: 成功 10 を目標（`EN_RECRUIT_BATCH_SIZE`、env で変更可）。
- 403: markDmNg で 90 日再送しない。
