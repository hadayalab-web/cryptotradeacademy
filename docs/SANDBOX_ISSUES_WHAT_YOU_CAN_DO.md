# サンドボックス障害について（あなたにできること）
**作成日**: 2026-02-01

---

## 状況

ここ数日、Cursor のサンドボックスで障害が発生している（例: `Failed to convert workspace SID`、PowerShell での `&&` 非対応など）。**サンドボックスは Cursor 側の実行環境**のため、リポジトリ内のコード変更では直せません。

---

## あなたにできること

| できること | 内容 |
|------------|------|
| **1. 実行時に権限を付与する** | ターミナルや「Run」でコマンドが失敗する場合、**「Run with all permissions」**（または同等の「サンドボックスを無効化して実行」）を選ぶと、多くの場合そのコマンドは成功します。 |
| **2. Cursor に報告する** | Help → Report Issue、または [Cursor Forum](https://forum.cursor.com/) で「Sandbox / Failed to convert workspace SID」などと検索し、同じ事象があればスレに参加、なければ新規で現象・OS・Cursor バージョンを書いて報告する。 |
| **3. Cursor を更新する** | サンドボックス周りの修正がリリースされている可能性があるため、最新版へアップデートして再現するか確認する。 |
| **4. ローカルで実行する** | AI に「Run」させず、あなたがローカルで `node scripts/...` を実行すれば、サンドボックスの影響を受けません。 |

---

## 補足

- サンドボックスは「ネットワーク・git・一部ファイル」を制限してコマンドを実行するため、**ネットワークが必要なスクリプト**（Grok API 呼び出しなど）は、サンドボックス障害時は `required_permissions: ['all']` や手動実行で対応するのが確実です。
- このファイルは、サンドボックス障害時に「何をすればよいか」をまとめたメモです。
