# X Reply Sales と X API 料金の対応

X API の料金表に基づき、x-reply-sales のどの処理がどのリソースで課金されるかを整理する。

## 料金表との対応

| X API リソース | 単価 | 課金単位 | x-reply-sales での該当処理 |
|----------------|------|----------|----------------------------|
| **投稿: 読み取り** | $0.005 | 取得したリソースごと | **list**: 検索 API（`tweets/search/recent`）で取得した**ツイート数**。1リクエストあたり maxResults 件（10〜100）。round-robin で 450 回 × 1ページ = 取得したツイート数だけ課金。 |
| **ユーザー: 読み取り** | $0.010 | 取得したリソースごと | **list**: 検索結果の `includes.users` で取得した**ユーザー数**。ツイート著者分。 |
| **コンテンツ: 作成** | $0.010 | リクエストごと | **send**: **リプライ投稿が成功したとき**のみ。403 なら投稿しないので課金されない。 |
| **DMインタラクション: 作成** | $0.015 | リクエストごと | **send**: **DM 送信が成功したとき**のみ。403 なら課金されない。 |
| **ユーザーインタラクション: 作成** | $0.015 | リクエストごと | **send**: **フォロー**（`followUser`）と**いいね**（`likeTweet`）。**実行したリクエストごとに課金**。相手がフォローバックするかどうかは関係ない。 |

## 課金されない／条件付き

- **リプライ 403**: 投稿しない → コンテンツ: 作成 は発生しない。
- **DM 403**: 送信しない → DMインタラクション: 作成 は発生しない。
- **フォロー・いいね**: API を叩いた時点で「ユーザーインタラクション: 作成」としてカウントされる想定（成功/失敗は要確認だが、実行回数で課金と考えるのが安全）。

## クレジット消費の注視ポイント

1. **list**: 「投稿: 読み取り」「ユーザー: 読み取り」＝ 検索で**取得したツイート数・ユーザー数**。round-robin の rounds が増えるほど取得数は増える。15件ブレーキで早期終了すれば取得数は抑えられる。
2. **send**: 「ユーザーインタラクション: 作成」＝ **フォロー数といいね数**。`X_REPLY_FOLLOW_BEFORE_SEND` と `X_REPLY_LIKE_BEFORE_DM` が有効な限り、試行する候補数に応じてフォロー・いいねが発火する。
3. リプライ・DM は 403 なら課金されないので、試行回数そのものより**フォローといいねの回数**を抑えたい場合は、キャップ（`X_REPLY_FOLLOW_CAP_PER_DAY` 等）やフラグで調整する。
