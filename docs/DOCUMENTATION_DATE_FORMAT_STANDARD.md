## 📋 目的

毎日同じようにドキュメントを管理するため、すべてのドキュメントに日付を必須で記載する標準を定めます。

---

## 📅 日付フォーマット標準

### 必須項目

すべてのドキュメントには以下の日付情報を**必ず**含めること：

```markdown
**作成日**: 2026-01-17
**作成日時**: 2026-01-17 14:07:03
**最終更新**: 2026-01-17 14:07:03
```

### フォーマット詳細

- **作成日**: 2026-01-17
- **作成日時**: 2026-01-17 14:07:03
- **最終更新**: 2026-01-17 14:07:03

### タイムゾーン

- **デフォルト**: JST（日本標準時）
- **明示的に記載する場合**: `2026-01-17 14:00:00 JST` または `2026-01-17 14:00:00 (UTC+9)`

## 🔄 更新時のルール

1. **ドキュメントを更新した場合**:
   - `**最終更新**` フィールドを現在の日時に更新
   - 更新内容を `## 更新履歴` セクションに追加（オプション）

2. **日次レポートの場合**:
   - 毎日新しいドキュメントを作成するか、既存ドキュメントを更新
   - 日付を必ず更新

3. **CEO報告メール送信時**:
   - メール件名に `[YYYY-MM-DD]` 形式で日付を自動追加
   - メール本文に報告日時を記載

## 📧 CEO報告メール

### 送信タイミング

以下の場合、CEO宛てメール報告を**必須**で送信：

1. **デプロイメント完了時**
2. **重要な機能実装完了時**
3. **エラー発生時**
4. **日次レポート（毎日）**

### メール件名フォーマット

```
[YYYY-MM-DD] 件名
```

例: `[2026-01-17] VSLワークフロー動作報告 - SUCCESS`

### メール送信方法

```bash
# 日次報告を送信
node scripts/send-ceo-daily-report.js

# または、プログラムから直接呼び出し
const { sendVSLWorkflowReport } = require('./services/email/ceo-report');
await sendVSLWorkflowReport({ status, summary, issues });
```

## 🔧 実装済み機能

### 日付フォーマット関数

`services/email/ceo-report.js` に以下の関数を実装：

- `formatDate(date)` - `YYYY-MM-DD` 形式
- `formatDateTime(date)` - `YYYY-MM-DD HH:MM:SS` 形式

### CEO報告メール関数

- `sendCEOReport()` - 汎用CEO報告メール
- `sendVSLWorkflowReport()` - VSLワークフロー専用報告
- `sendDeploymentReport()` - デプロイメント専用報告
