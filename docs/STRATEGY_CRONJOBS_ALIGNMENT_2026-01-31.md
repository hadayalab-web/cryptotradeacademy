# 戦略とCronJobsの整合性

**作成日**: 2026-01-31  
**目的**: トレード依存症ターゲット・試薬/処方箋設計に、Cronで回している仕組みが基づいているかを整理し、ギャップを明示する。

---

## 1. ビジネス戦略（設計の前提）

- **ターゲット**: トレード依存症のトレーダー（「絶望的な最適化者」）。
- **無料版（Minimal Version）**: **試薬** — 反応を見る・トリアージする入口。治すわけではない。
- **有料版（Regular Briefing）**: **処方箋** — 深い分析・シグナル・心理サポートとしての「処方」。
- **設計意図**: トレードを止めさせる（完治させる）のではなく、**我々の配信がないと回らなくなる**状態をつくる。依存先を「市場の衝動」から「Trap Defence の配信」に寄せる。

→ この設計に、Cronで回している全ジョブが従っている必要がある。

## 3. 現状CronJobs と 試薬／処方箋の対応

| Cron | スケジュール | 設計上の役割 | 備考 |
|------|--------------|--------------|------|
| `/api/cron` | 15分ごと | **試薬＋処方箋** | TG: 無料版・有料版の定期/緊急配信。戦略どおり「15分でFOMO」の核。 |
| `/api/x-post-minimal-version-cron` | 0,7,12,15,23時 UTC | **試薬** | X 無料版スレッド（Hook / Quick Reads / Psych / Poll+CTA）。 |
| `/api/x-post-free-report` | 4,10,17,19時 30分 UTC | **試薬** | X 無料レポート（ストック活用）。 |
| `/api/x-quote-repost-*` | 6分ごと等（言語分散） | **試薬への誘導** | 引用リポスト → Whop 無料版 or t.me。トリアージ入口。 |
| `/api/vsl1-post` | 1,13,21時 UTC | ファネル | VSL1。 |
| `/api/vsl2-*`, `vsl1-reminder` | 毎時等 | ファネル | VSL2・リマインド。 |
| `/api/promo-stock-monitor` | 15分ごと | 運用 | プロモ在庫監視。 |

- **試薬**に紐づく: `cron`（無料TG）、`x-post-minimal-version-cron`、`x-post-free-report`、`x-quote-repost-*`。
- **処方箋**に紐づく: `cron`（有料TG Regular Briefing）。  
→ 現状、「試薬」は複数Cronでカバーされているが、「処方箋」は `cron` の定期/緊急スロットに依存しているだけであり、**処方箋の「ないと回らない」リズムがCronレベルで明示されているわけではない**。

---

## 4. まだまだ不十分な点（ギャップ）

1. **処方箋のリズムがCron設計に明示されていない**  
   「毎日この時刻に処方箋がないと不安」というリズム（例: 1日1〜2回の確定時刻）が、Cronのスケジュールやジョブ名として表現されていない。`cron` 内の `isRegularSlot` 等に依存しており、**設計意図（配信依存）がCron一覧から読み取れない**。

2. **試薬→処方箋の遷移がCronで表現されていない**  
   無料→有料の「試薬で反応を見て、処方箋へ誘導」という流れが、Cronの実行順・時間帯・条件として意図的に組まれているかが不明。現状は各ジョブが個別スケジュールで動いているだけに見える。

3. **「配信がないといけなくなる」時刻の固定**  
   戦略では「配信がないと回らなくする」設計。そのためには「毎日この時刻に必ず処方箋が出る」ような**固定時刻**が有効。現状の 15 分ごとだけでは「いつ来るか」の予測可能性が弱く、依存を「習慣」に落とし込みにくい。

4. **監視・改善指標が戦略と紐づいていない**  
   Cron の成否だけでなく、「試薬の反応（クリック・TRAP リプライ）」「処方箋の開封・継続」など、**設計（試薬／処方箋／依存）に沿ったKPI**がCron/配信ログと紐づいていない可能性がある。

---

## 5. 次のステップ（提案）

1. **処方箋の「確定時刻」をCronで明示する**  
   例: 有料版レポートを「毎日 UTC 6:00 / 18:00」など固定時刻で必ず1本出すジョブを設ける（または `cron` 内でその時刻を最優先スロットにする）。vercel.json の crons に「Regular Briefing 固定時刻」と分かる名前・コメントを付与する。

2. **試薬→処方箋の流れをCron設計に落とす**  
   例: 無料版X（試薬）の直後に、同じユーザー向けに「処方箋の案内」が出るような実行順・時間帯を意図的に組む。ドキュメントとCronのコメントで「試薬→処方箋」と書く。

3. **戦略KPIの定義とログ紐づけ**  
   試薬（Minimal）・処方箋（Regular）それぞれについて、「反応」「開封」「継続」などの指標を定義し、Cron/配信ログ・Whopと紐づけて見られるようにする。

4. **既存ドキュメントとの参照を常に張る**  
   Cron の変更時は、`TRADING_ADDICTION_DEPENDENCY_STRATEGY_COMPLETE_2026-01-28.md` の「試薬／処方箋／配信依存」の記述を参照し、設計から外れないようにする。

---

**まとめ**: 現状のCronは「試薬」を多チャネルで回しているが、**処方箋の「配信がないと回らない」リズムがCron設計として明示されておらず、試薬→処方箋の遷移もCronレベルでは不十分**。上記のギャップを埋めることで、Cronで回している仕組みが設計に基づいたものになる。
