# BuzzWeave 戦略の根拠（Gemini 協働）

## 1. 経緯と反省

- **確認不足**: 当初から「Gemini と協働しなさい」と伝えられていたにもかかわらず、Cursor 側でそれを確認せず、Gemini を呼ばずに実装していた。
- **根拠の欠如**: 投稿者リーチの重み 0.2・正規化式・HYPE/CTR のバランスなど、**なぜその数値か**を説明していなかった。Copilot レポートに「根拠がない」と指摘してきたのと同様に、当方の独断も根拠を明示していなかった。

**対応**: `scripts/buzzweave-cmo-strategy-session.js` で CSO（Cursor）が CMO（Gemini）を API で呼び出し、**推奨ごとに根拠を付けた**戦略を取得。その結果に基づき実装を更新し、本ドキュメントで「何を・なぜ」を対応付けた。

## 4. 未実装・検証予定（Gemini ラウンド2）

- **velocity が一定以下の場合に author reach を 0 にする足切り**: CMO は「死に体アカウント」除外を推奨。実装する場合は閾値の根拠（何を測るか）を決めてから入れる。
- **CopyFit の閾値厳格化・ベクトル検索**: CMO は「CopyFit 高比重」を推奨。現状はキーワードベース。LLM/ベクトル検索のコストと効果の検証後にロールアウトする想定。

## 5. 運用

- パラメータは環境変数で上書き可能（`BUZZWEAVE_IMPRESSION_W_*`, `BUZZWEAVE_HYPE_BOOST`, `BUZZWEAVE_CTR_BOOST`, `BUZZWEAVE_LOW_VOLUME_LANGS`, `BUZZWEAVE_AR_WINDOW_MIN` 等）。
- 戦略の見直し時は、再度 `buzzweave-cmo-strategy-session.js` を実行し、CMO の根拠付き推奨を取得してから変更する。
