# X API v2 1日の投稿数上限

## 🚨 重要: 従量課金制への移行

**2025年10月以降、X APIは従量課金制（Pay-Per-Use）モデルに移行しました。**

### 旧モデル（サブスクリプション）→ 新モデル（従量課金制）

- **旧モデル**: 固定月額料金（$200/month または $5,000/month）+ プラン別レート制限
- **新モデル**: 使用量ベースの料金 + **レート制限は残存**（ただし緩和）

## 📊 レート制限（POST /2/tweets）

レート制限は従量課金制移行後も**残存**していますが、一部緩和されています：

### Free Tier
- **17投稿 / 24時間**（ユーザー単位）
- **17投稿 / 24時間**（アプリ単位）

### Basic Tier
- **100投稿 / 24時間**（ユーザー単位）
- **1,667投稿 / 24時間**（アプリ単位）

### Pro Tier
- **100投稿 / 15分**（ユーザー単位）
- **10,000投稿 / 24時間**（アプリ単位）

## 💰 従量課金制の料金（暫定価格）

**注意**: パイロット期間中の暫定価格です。将来的な変更の可能性があります。

| リソース | 単価 | 備考 |
|---------|------|------|
| **投稿作成**（POST /2/tweets） | **料金あり** | 暫定価格（詳細未公開） |
| 投稿読み取り | $0.005 / リソース | 10kリソース = $50.00 |
| ユーザー読み取り | $0.010 / リソース | - |
| DMイベント読み取り | $0.015 / リソース | - |

### 新モデルの特徴（公式ドキュメントより）

公式ドキュメント（[X API Introduction](https://docs.x.com/x-api/introduction)）によると、従量課金制の主な特徴は：

1. **柔軟なスケーリング（Flexible scaling）**: 小規模から始めて成長可能。コストは実際の使用量に応じてスケール
2. **契約不要（No commitments）**: 契約や最小支出なし。いつでも停止可能
3. **リアルタイム追跡（Real-time tracking）**: 開発者コンソールで使用量とコストをリアルタイムで監視
4. **クレジットベース（Credit-based）**: 事前にクレジットを購入し、API使用時に差し引かれる

### 新モデルのメリット

1. **柔軟性**: 契約の制約なく、必要に応じてスケールアップ/ダウン可能
2. **アクセシビリティ**: 使用量に応じて費用が変動するため、小規模開発でも利用しやすくなった
3. **拡張アクセス**: エンドポイントごとのレート制限を緩和、プランによる従来の制約からも解放
4. **リアルタイム監視**: 開発者コンソールでクレジット購入、使用量監視が可能
5. **サブスクリプション不要**: 固定月額料金なし、使用した分だけ支払い
6. **月額上限なし**: レート制限内であれば、使用量に制限なし

## 🔍 現在の実装状況

コード内では`checkDailyPostLimit`関数で`maxPosts = 45`が設定されています。これは：
- Basic Tierの100投稿/日のレート制限を考慮した安全な値
- 従量課金制移行後も、レート制限は残存しているため、この設定は有効

## 💡 理論上の最大投稿数

### Basic Tier（ユーザー単位）
- **1日最大: 100投稿**（レート制限）
- 15分あたり: 約6.25投稿（100 ÷ 16 = 6.25）
- 1時間あたり: 約4.17投稿（100 ÷ 24 = 4.17）
- **料金**: 使用量ベース（投稿作成の暫定価格に依存）

### Pro Tier（ユーザー単位）
- **15分あたり: 100投稿**（レート制限）
- **1時間あたり: 400投稿**（100 × 4）
- **1日最大: 9,600投稿**（100 × 4 × 24 = 9,600）
- **ただし、アプリ単位の制限: 10,000投稿 / 24時間**
- **料金**: 使用量ベース（投稿作成の暫定価格に依存）

## ⚠️ 重要な注意事項

1. **レート制限は残存**: 従量課金制移行後も、レート制限は引き続き適用されます
2. **料金体系の変更**: 固定月額から使用量ベースに変更。レート制限内であれば、使用量に応じて料金が発生
3. **ユーザー単位の制限**: OAuth 1.0a User Context認証を使用する場合、各ユーザーのアクセストークンごとに制限が適用されます
4. **アプリ単位の制限**: OAuth 2.0 Bearer Token（App-only認証）を使用する場合、アプリ全体で制限が適用されます
5. **現在の実装**: OAuth 1.0a User Context認証を使用しているため、**ユーザー単位の制限**が適用されます
6. **暫定価格**: パイロット期間中のため、価格は将来的に変更される可能性があります

## 📝 推奨事項

### 従量課金制での運用

現在の実装では、Basic Tierの場合：
- **1日最大100投稿**（レート制限）
- 現在の設定（45投稿/日）は安全な範囲内
- **料金**: 使用量ベース（投稿作成の暫定価格に依存）

Pro Tierにアップグレードした場合：
- **1日最大9,600投稿**（ユーザー単位、理論上）
- ただし、アプリ単位の制限（10,000投稿/24時間）も考慮する必要があります
- **料金**: 使用量ベース（投稿作成の暫定価格に依存）

### コスト管理

1. **使用量監視**: 開発者コンソールでリアルタイム使用量を監視
2. **予算設定**: 月次予算の上限を設定し、アラートを有効化
3. **クレジット購入**: 必要に応じてクレジットを購入
