## 🔍 2週目で確認された課題

### 1. 階層の偏り（CRITICAL - 全言語共通、未改善）

**問題**: すべての言語で100%が「top」階層（followerCount ≥ 10,000）

| 言語 | Top階層 | Mid階層 | Bottom階層 |
|------|---------|---------|------------|
| EN | 210 (100%) | 0 (0%) | 0 (0%) |
| ES | 168 (100%) | 0 (0%) | 0 (0%) |
| PT-BR | 158 (100%) | 0 (0%) | 0 (0%) |
| AR | 112 (100%) | 0 (0%) | 0 (0%) |
| JA | 98 (100%) | 0 (0%) | 0 (0%) |
| KO | 78 (100%) | 0 (0%) | 0 (0%) |

**影響**:
- SSOTで推奨された階層分布（top/mid/bottom）が達成できない
- ローテーション戦略の多様性が失われる
- 中規模・小規模インフルエンサーの発見機会を逃している

**解決策（未実施）**:
- Grokプロンプトでフォロワー数の範囲を明示的に指定
- 階層ごとに別々のリクエストを送信
- 後処理での階層調整

### 2. リトライ上限に達したバッチ（HIGH - 改善されたが継続）

**問題**: 一部の言語でリトライ上限（3回）に達して失敗

| 言語 | 失敗バッチ数 | 失敗率 | リトライ上限に達したバッチ |
|------|-------------|--------|--------------------------|
| EN | 0 | 0% | なし |
| ES | 0 | 0% | なし |
| PT-BR | 2 | 40% | バッチ4, 5 |
| AR | 0 | 0% | なし |
| JA | 1 | 25% | バッチ1 |
| KO | 2 | 33% | バッチ1, 4 |

**1週目との比較**:
- PT-BR: 1 → 2（悪化）
- JA: 4 → 1（改善）
- KO: 6 → 2（大幅改善）

**観察**:
- EN/ES/ARではリトライ上限に達する前に成功
- PT-BR/JA/KOでは一部のバッチでリトライ上限に達して失敗
- 1週目と比較して全体的に改善傾向

**解決策（部分的に実施済み）**:
- リトライロジックは有効に機能しているが、一部の言語で上限が不足
- 言語別のリトライ戦略が必要（KO/JA: 10回、PT-BR: 5回）

### 3. Username長さ制限による除外（MEDIUM - 継続）

**問題**: 16文字以上のusernameが自動除外される

| 言語 | 除外数（推定） | 除外率 | 主な除外例 |
|------|--------------|--------|-----------|
| EN | 0-1人 | 0-0.5% | - |

| AR | 0人 | 0% | - |
| JA | 2人 | 2.0% | satoshinakamotojp, cryptoanalyst_jp |
| KO | 0人 | 0% | - |

**観察**:
- PT-BRとJAで継続的に除外が発生
- 1週目と比較して除外率は低下傾向

**解決策（未実施）**:
- Grokプロンプトで「usernameは15文字以内」を明示
- 長いusernameのアカウントを避けるように指示

### 4. 重複の増加（MEDIUM - 改善されたが継続）

**問題**: 一部のバッチで重複が増加

| 言語 | 重複が顕著なバッチ | 最大重複率 |

- JA: なし → 33%（新規発生）

## 🎯 残存課題と優先順位

### 優先度1: CRITICAL（即座に実施）

#### 1.1 階層バランスの改善（未実施）

**問題**: すべての言語で100%が「top」階層

**解決策**:
1. Grokプロンプトの調整:
   - フォロワー数の範囲を明示的に指定
   - Top: 10,000-500,000 followers
   - Mid: 1,000-9,999 followers
   - Bottom: 100-999 followers

2. 段階的取得:
   - 階層ごとに別々のリクエストを送信
   - 各階層の目標数を設定（例: Top 60%, Mid 30%, Bottom 10%）

**期待効果**: SSOTで推奨された階層分布を達成

#### 1.2 リトライロジックの強化（部分的に実施）

**問題**: PT-BR、KO、JAで一部のバッチがリトライ上限に達して失敗

**解決策**:
1. 言語別のリトライ回数:
   - KO/JA: 10回（現状: 3回）
   - PT-BR: 5回（現状: 3回）
   - EN/ES/AR: 3回（現状維持）

2. リトライ間隔の延長:
   - 現在: 2s → 4s → 6s
   - 提案: 2s → 4s → 8s → 16s → 32s → 64s → 128s → 256s → 512s → 1024s

**期待効果**: PT-BRの達成率を94.0% → 100%、KOの達成率を92.9% → 100%

### 優先度2: HIGH（早期に実施）

#### 2.1 重複防止の強化（部分的に実施）

**問題**: PT-BR、JA、KOで一部のバッチで重複が増加

**解決策**:
1. 取得済みリストの提供:
   - Grokプロンプトに取得済みのusernameリストを渡す
   - 「既に取得済みのインフルエンサーは除外」を明示

2. 多様性の要求:
   - Grokプロンプトで「多様なインフルエンサーを返却」を明示
   - 「同じアカウントを繰り返し返却しない」を明示

**期待効果**: PT-BRの重複率を71% → 30%以下、JA/KOの重複率を20-33% → 10%以下

#### 2.2 Username長さ制限の見直し（未実施）

**問題**: PT-BR、JAで16文字以上のusernameが自動除外される

**解決策**:
1. Grokプロンプトの明示:
   - 「usernameは15文字以内」を明示
   - 長いusernameのアカウントを避けるように指示

**期待効果**: 除外率を1-2% → 0.5%以下
