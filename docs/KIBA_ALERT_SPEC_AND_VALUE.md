# KIBA アラート仕様と「渇望されるプロダクト」像

**KIBA の目的は、相場操作によってトレンド転換が起こることを予測してアラートを出すことである。つまり相場操作に乗っかって、先回りして、ポジションを取れるようにする。** フロー・ウォール・流動性・センチメントなど相場操作（仕手）に当たる動きを検知し、転換の可能性が高まったタイミングで Regular に配信する。

**KIBA は有料版（Regular Briefing）の特典である。** 無料版（Minimal）には配信されない。

## 1. どんなときに発火するか

- **トリガー**: 5分ごとの Cron (`/api/kiba-5min`) で `runKibaEngine` を実行。
- **発火条件**（すべて満たすとき）:
  - **kibaScore ≥ 55**（閾値 `TRIGGER_SCORE_MIN`）
  - **impact が ELEVATED / HIGH / CRITICAL** のいずれか  
    （55–64: ELEVATED, 65–84: HIGH, 85+: CRITICAL）
  - **CQ データあり**（`hasCq`。ないときはスコア 30 キャップで発火しない）
  - **1時間コールダウン**: 直近 1 時間内に同じ or 下位レベルで発火済みなら今回の ELEVATED は送らない（二重送信防止）

- **スコアの元**: CQ（取引所フロー・ネットフロー・MPI 等）＋ X センチメントを **6 つの検知器**で評価し、加重平均して 0–100 に正規化。
  - flow (0.25), whale (0.3), liquidity (0.2), sentiment (0.2), retail (0.05), algo (0)

---

## 2. どんなアラートを配信するか

- **配信先**: **Regular 購読者だけ**。  
  `sendMessageToChannel(text, "BTC", marketCode)` により、**言語別 Regular 用 Telegram チャンネル**（`TELEGRAM_CHAT_ID_BTC_EN` / `_JA` / `_ES` / `_KO` / `_PT_BR` / `_AR`）に送る。ユーザー向けには **KIBA** の名前を出してよい。
- **文言**: `formatCriticalAlert(snapshot, lang)` で **6 言語** を生成。タイトルに **KIBA** を冠する（例: 「KIBA — 重要マーケットアラート」）。

### アラート本文の構成（例: 日本語）

1. **タイトル**（impact に応じて・トレンド転換の予測であることを明示）  
   - CRITICAL: 「重要：トレンド転換シグナル」  
   - HIGH: 「トレンド転換の可能性高」  
   - ELEVATED: 「トレンド転換に注意」
2. **リード**（相場操作に乗り先回りしてポジションを取る材料である旨）  
   - 「相場操作によるトレンド転換を予測。先回りしてポジションを取る材料としてご活用ください。」
3. **市場の文脈**  
   - BTC: 価格 / 24h 変化率 / レジーム  
   - マクロ: NASDAQ レジーム / GOLD バイアス / マクロ Risk On/Off
4. **注意書き**  
   - 「具体的な売買シグナルではなく、ポジションの材料として使ってください。」

（他言語は `services/ai/gpt5mini.js` の `ALERT_I18N` で同構造）

## 3. どんなトレーダーに「渇望される」プロダクトか（意図と現状）

- **意図している価値**  
  - **相場操作によるトレンド転換を予測 → 先回りしてポジションを取れるようにする**：5分単位でフロー・ウォール・流動性・センチメントなど**相場操作（仕手）に当たる動き**を検知し、転換の可能性が高まったとき **Regular だけに配信**する。受け手は**相場操作に乗っかって、先回りしてポジションを取る**材料として使う。  
  - Trap Defence の「70% は何もしない。明確な優位が出るまで待つ」と組み合わせ、**「今は待つべきか / 操作の材料が出たか」を判断するためのコンテキスト**として使う。  
  - 売買シグナルではなく「ポジションの材料」と明記しているので、**自分で判断したいが、操作に乗り遅れたくないトレーダー**向け。

- **訴求コピーでの位置づけ**  
  - Minimal → Regular のアップセルで「5分パルス（KIBA）+ Exit Map」「見逃しゼロ」と説明。  
  - DEFEND50 で「Regular = 5分パルス（KIBA）+ Exit Map」としている。

- **現状のギャップ**  
  - 過去は suppression が厳しく **一度も発火せず**、ユーザーは「渇望」する前にアラートそのものを受け取れていなかった。  
  - suppression を「CQ なし時のみキャップ」に緩めたことで、**rawScore が 55 以上かつ CQ ありのときに、初めて「届く」アラート**になる。

## 4. まとめ

| 項目 | 内容 |
|------|------|
| **いつ** | 5分 Cron で kibaScore ≥ 55 & impact ∈ {ELEVATED,HIGH,CRITICAL} & CQ あり & 1h コールダウン通過 |
| **何を** | 重要度別タイトル + BTC/マクロの文脈 + 「売買シグナルではなく材料」の注意（6言語） |
| **誰に** | Regular 購読者（言語別 Telegram チャンネル）のみ |
| **渇望される像** | 「待つべきか・材料が出たか」を逃したくないが、自分で判断したいトレーダー向けの「5分パルス」コンテキスト |
