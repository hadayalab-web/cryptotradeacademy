## 🎯 実行方針

### 基本原則

1. **量より質**: 10人の完璧なインフルエンサー > 50人の不完全なインフルエンサー
2. **段階的実行**: 一言語ずつ、小さいバッチで確実に
3. **厳格な検証**: 保存前・保存後の検証を実施
4. **バックアップ**: 各保存前にバックアップを作成

---

## 📋 実行手順

### 方法1: 一言語ずつ実行（推奨）

#### EN（英語）から開始

```bash
# Windows
scripts\run-discover-influencers-en.bat

# または直接
node scripts/discover-influencers-single-lang-robust.js en 210
```

#### 他の言語も同様に

```bash
# ES（スペイン語）
node scripts/discover-influencers-single-lang-robust.js es 168

# PT-BR（ポルトガル語）
node scripts/discover-influencers-single-lang-robust.js pt-br 168

# AR（アラビア語）
node scripts/discover-influencers-single-lang-robust.js ar 112

# JA（日本語）
node scripts/discover-influencers-single-lang-robust.js ja 98

# KO（韓国語）
node scripts/discover-influencers-single-lang-robust.js ko 84
```

---

### 方法2: 全言語を自動実行

```bash
node scripts/discover-influencers-all-langs-stepwise.js
```

**注意**: この方法は時間がかかります（各言語で5-10分）。エラーが発生した場合、途中で停止する可能性があります。

## 🔍 検証プロセス

### 保存前検証

スクリプトは以下の検証を自動的に実行します：

1. **tweetId検証**: 18-19桁の数値
2. **username検証**: @なし、1-15文字
3. **tweetText検証**: 1-280文字、空でない
4. **followerCount検証**: > 0
5. **engagementRate検証**: 0-1の範囲
6. **recentImpressions検証**: >= 0
7. **重複チェック**: tweetIdベース

### 保存後検証

スクリプトは保存後にファイルを読み込んで以下を確認します：

1. ファイルが正しく保存されたか
2. データ数が一致するか
3. JSON形式が正しいか

## 🛡️ 過去の問題への対策

### 問題1: DBに保存できなかった

**対策**:
- ファイルベースストレージ（Git管理）を使用
- 各バッチ後に保存（段階的保存）
- エラーハンドリングを強化

### 問題2: 保存後、全消去された

**対策**:
- 各保存前にバックアップを作成
- 保存後検証を実施
- 既存データを読み込んで重複チェック

### 問題3: 情報に不備があった

**対策**:
- 厳格な検証ロジックを実装
- 必須フィールドのチェック
- データ形式の検証（tweetId、username、tweetText）

## 🚨 トラブルシューティング

### エラー: "Grokから取得失敗（0人）"

**原因**: Grok APIのエラー、または検索条件が厳しすぎる

**対策**:
- バッチサイズを小さくする（10-15人）
- 言語を確認する
- Grok APIのレート制限を確認する

### エラー: "検証後0人"

**原因**: Grokが返したデータが検証を通過しなかった

**対策**:
- Grokプロンプトを確認する
- 検証ログを確認して、どのフィールドが問題か確認する
- バッチサイズを小さくして再試行する

### エラー: "保存失敗"

**原因**: ファイルシステムのエラー、または権限の問題

**対策**:
- ディレクトリの権限を確認する
- ディスク容量を確認する
- バックアップを確認する
