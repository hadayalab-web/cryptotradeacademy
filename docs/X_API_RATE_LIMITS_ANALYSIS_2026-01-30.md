## ⚠️ レート制限チェック

### Per User制限（OAuth 1.0a User Context）

**制限**: **100/15min** = **400/時間** = **9,600/24hrs**

**現在の実装**:
- 環境変数 `X_MAX_HOURLY_POSTS` のデフォルト値: **100/時間**
- これは **Per User制限（400/時間）の25%** に設定されている

**分析**:
- ✅ **安全マージン**: 現在の実装は制限の25%を使用しているため、安全マージンが十分にある
- ✅ **1日あたりの投稿数**: 推定408投稿/日は、Per User制限（9,600/24hrs）の **4.25%** に相当
- ✅ **15分あたりの投稿数**: 最大約40投稿/15min（UTC 0時）は、Per User制限（100/15min）の **40%** に相当

### レート制限エラーハンドリング

現在の実装では、`services/x/client.js`でレート制限エラー（429）を処理しています：

## 💰 X API コスト

### 料金体系

X APIは **Pay-per-usage（使用量課金）** モデルです：

| プラン | 月額料金 | 含まれるリクエスト数 | 追加リクエスト |
|-------|---------|------------------|--------------|
| **Free** | $0 | 1,500ツイート/月 | - |
| **Basic** | $100/月 | 3,000ツイート/月 | - |
| **Pro** | $5,000/月 | 1,000,000ツイート/月 | - |
| **Enterprise** | カスタム | カスタム | カスタム |

**注意**: 
- レート制限と課金は **別々** です
- レート制限内でも使用量に応じて課金されます
- レート制限を超えても追加料金は発生しません（429エラーが返される）

### 現在の使用量推定

**1日あたりの投稿数**: 約408投稿/日  
**1ヶ月あたりの投稿数**: 約 **12,240投稿/月** (408 × 30)

**プラン比較**:
- **Free**: 1,500ツイート/月 → **不足**（12,240 > 1,500）
- **Basic**: 3,000ツイート/月 → **不足**（12,240 > 3,000）
- **Pro**: 1,000,000ツイート/月 → **十分**（12,240 << 1,000,000）

**推奨**: **Proプラン（$5,000/月）** が必要

## 🚨 潜在的な問題

### 1. 15分あたりのレート制限超過リスク

**問題**: UTC 0時やUTC 8時など、複数言語が同時に処理される時間帯では、15分あたりの投稿数が100を超える可能性がある

**例: UTC 0時**
- AR: 8人、EN: 32人 = **合計40投稿**
- これは15分以内に実行される可能性がある
- Per User制限（100/15min）の **40%** に相当

**対策**: 
- ✅ 現在の実装では `X_MAX_HOURLY_POSTS` で1時間あたりの投稿数を制限している（デフォルト: 100/時間）
- ⚠️ しかし、15分あたりの制限チェックは実装されていない

**推奨**: 15分あたりのレート制限チェックを追加することを検討

### 2. レート制限エラーのリトライロジック

**現状**: 
- ✅ `services/x/client.js`でレート制限エラー（429）を処理
- ✅ 指数バックオフでリトライ（最大3回）
- ✅ `x-rate-limit-reset`ヘッダーを確認して待機時間を計算

**問題**: 
- ⚠️ リトライが失敗した場合、投稿がスキップされる
- ⚠️ レート制限エラーが頻繁に発生する場合、投稿成功率が低下する可能性がある

**推奨**: 
- レート制限エラーが発生した場合、次のCron実行まで待機するロジックを追加することを検討

async function check15MinutePostLimit(lang, dateString, currentMinute) {
