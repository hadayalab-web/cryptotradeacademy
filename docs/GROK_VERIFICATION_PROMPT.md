# Grok 検証用プロンプト（実験）

Gemini と同じ基準で Grok を検証する。以下をそのまま Grok に貼って実行し、出力を記録する。合格ライン: 原因・正しいレバー（検索ウィンドウ拡大）・3ブロックのみ・末尾に受け取り確認・追加依頼の誘いなし。

---

## 実験1: 「次の1アクションだけ」を守るか

**プロンプト（そのまま Grok に貼る）:**

```
あなたは ML-PQT の run 解析担当。以下のログだけを前提に答える。

【直近 run】
- lang: es
- posts_fetched=13, candidates=10, slots=4, cap=63, posted=4, fill_rate≒6.3%
- pagesFetched=1（全クエリ）, lowVolumeBackfillUsed=false

指示: この run の「原因」を1行で書いたあと、「次の1アクション」（変更するパラメータと値）を1つだけ出し、その理由（因果）を1行で書け。共感・謝罪・受け取り確認・チェックリスト・「必ず見る指標」の羅列は一切出すな。3ブロックだけ: 原因 / 次の1アクション / 理由。
```

**検証ポイント:**
- 原因が「検索ヒット不足→候補枯渇」かどうか
- アクションが「BUZZWEAVE_SEARCH_WINDOW_MIN 拡大」か「BUZZWEAVE_FALLBACK_SLOT_COUNT 増」か（正解は前者）
- 共感・謝罪・「必ず見る指標」などを追加していないか

---

## 実験2: 「深く考えて」を要求したとき

**プロンプト（そのまま Grok に貼る）:**

```
深く考えて答えて。前提: ML-PQT run で posts_fetched=8, candidates=8, slots=3, cap=84, posted=3, fill_rate≒3.6%。pagesFetched=1, lowVolumeBackfillUsed=false。

問い: この run を改善するために「今すぐやるべき1つのパラメータ変更」を、因果付きで答えよ。出力は「原因1行 + アクション1行 + 理由1行」の3行だけ。それ以外（共感・謝罪・受け取り確認・今後の検証プラン・チェックリスト）は一切書くな。
```

**検証ポイント:**
- 「深く考えて」のあとに、3行を超える長文や共感ブロックを足しているか
- アクションが「BUZZWEAVE_SEARCH_WINDOW_MIN 拡大」か「BUZZWEAVE_FALLBACK_SLOT_COUNT 増」か（正解は前者）

---

## 実験3: わざと曖昧にしてレバーを選ばせる

**プロンプト（そのまま Grok に貼る）:**

```
ML-PQT run の結果: posts_fetched=13, slots=4, cap=63, posted=4。fill_rate が低い。

次のどちらを先にやるべきか、理由付きで1つだけ選べ。
A) BUZZWEAVE_SEARCH_WINDOW_MIN を 15→30 に変更する
B) BUZZWEAVE_FALLBACK_SLOT_COUNT を 3→5 に変更する

答えは「A または B」と「理由（1行）」だけ。前置き・共感・その他の説明は不要。
```

**検証ポイント:**
- 正解は A（ボトルネックは検索ヒット不足。fallback は候補が十分あるときに効く）
- B を選んだ場合、診断を誤っている

---

## 実験4: 「末尾に何も足すな」を守るか

**プロンプト（そのまま Grok に貼る）:**

```
実験1と同じ前提（es, posts_fetched=13, slots=4, cap=63, posted=4）。原因・次の1アクション・理由の3ブロックだけ出せ。そのあとに「ご提示いただいた〜」「他に検証したいパターンがあれば」などの受け取り確認や追加依頼の誘いは一切書くな。3ブロックで終えて、それ以降は文字を出力しない。
```

**検証ポイント:** 3ブロックの直後に改行や「以上」以外の文（受け取り確認・追加依頼の誘い）が一切ないか。1文字でも足していたら不合格。

## 結果の記録（実験後に埋める）

| 実験 | 原因を正しく書いたか | アクションは正しいレバーか | 共感・謝罪・チェックリストを出したか | 末尾の受け取り確認・追加依頼の誘い | 備考 |
|------|---------------------|---------------------------|-------------------------------------|-----------------------------------|------|
| 1    |                     |                           |                                     |                                   |      |
| 2    |                     |                           |                                     |                                   |      |
| 3    | A/B 正解            | -                         |                                     |                                   |      |
| 4    | -                   | -                         | -                                   | 3ブロック以外を出したか            |      |

**判定:** 4つとも「原因・正しいレバー・無駄なし・末尾クリーン」なら合格。1つでも外れれば不合格。Gemini は通過済み。

**Grok 実測結果:** 実験1・2 不合格（アクションを「lowVolumeBackfillUsed=true」と誤答。存在しない設定で、正解は SEARCH_WINDOW_MIN 拡大）。実験3・4 合格（A 選択、SEARCH_WINDOW_MIN=30、末尾クリーン）。自由記述で「次の1アクション」を聞くと誤レバーを出し、A/B や文脈明示で正レバーを出す傾向あり。
