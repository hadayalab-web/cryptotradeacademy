# 仕手Bot攻略：戦略・戦術とAI視点の秘策

**X のデータはパターン化されているのでスキャンしやすい。** 投稿はテキスト・メトリクス・時刻・作者が揃い、検索APIで「直近・キーワード・言語」で取れる。Bot の波・煽りキーワード・engagement の立ち上がりをパターンとして読めるから、仕手Bot攻略の検出・優先・バースト検知をそのままかけやすい。

**しかも Bot が気持ち悪いぐらいウヨウヨいる。** 供給は尽きない。だから「多く拾い、多く撃つ」で遠慮なく攻めてよい。

---

## 1. 戦略（何をやっているか）

- **目的**: 仕手Botの攻略を通じて提灯救済に寄与し、教育コンテンツ（VSL/LP）へ誘導する。
- **前提**: 仕手系投稿の多くはBot。Bot が集客し、提灯がそこに群がる。Bot を除外せず、**その流れに乗る**。
- **我々の手**: 同じスレに「構造・トラップ回避」＋リンクを載せ、提灯に届ける。Bot 相手なら遠慮なく攻める。

---

## 2. 戦術（いまやっていること）

| 戦術 | 内容 |
|------|------|
| **多く拾い、多く撃つ** | 条件で絞りすぎない。検索 → NG 除外 → engagement×hype でソート → cap まで引用。 |
| **Bot が集客したスレを優先** | 煽りキーワード（hypeBonus）をソートに効かせ、Bot っぽい投稿を上に。検索クエリにも pump, moon, 急騰 等を入れる。 |
| **スレに 2 回出る** | Reply-first（先にリプライ→引用）で、Bot スレに群がった提灯の TL に載りやすくする。run の 50% で実施。 |
| **6言語・時間帯合わせ** | UTC ブロックで言語を切り替え、各圏の活動時間に近いタイミングで投下。 |
| **シンプル選定** | Fisherman 必須・2〜7分窓・中央値で捨てない。本数を確保してからデータで効く条件を見る。 |

---

## 3. AI視点の秘策（これから効かせられること）

Bot と提灯の構造を「データとパターン」で扱うと、人間の直感だけでは拾いにくいレバーが出てくる。

### 3.1 感情に同意してから軸をずらす（コピー）

- **観察**: 提灯は「乗り遅れるな」「Pumping」に反応してスレに来ている。いきなり「危険だ」と言うと無視されやすい。
- **秘策**: **先に感情に同意する一行**を入れてから「でもここだけ確認」とずらす。例：「確かに動いてる。その前にここだけ見ておくと損しにくい」。
- **実装**: テンプレの冒頭を「同意フック」に統一し、引用元の語彙（mirrorWords）を強く使う。既存の mirrorWords をさらに効かせる。

### 3.2 爆発直後の「初動リプライ」を奪う

- **観察**: Bot 投稿が伸び始めた直後、最初の数リプライが TL に残りやすい。
- **秘策**: **投稿年齢が短い（例: 2〜15分）かつ engagement が付き始めている**投稿をさらに優先する。= 「今まさに伸びている」スレに早く乗る。
- **実装**: シンプル選定のスコアに「新しさボーナス」を足す。例: `score *= (1 + 0.2 * freshness)`。検索窓を短くするオプションと組み合わせる。

### 3.3 同一キャンペーンは 1 本だけ引用する（クラスタ引用）

- **観察**: Bot ネットは同じ文言を複数アカで流す。提灯は「一番伸びた 1 本」のスレに集中する。
- **秘策**: **似たテキストの投稿は 1 クラスタとみなし、その中で engagement 最大の 1 本だけ引用**する。同じメッセージに何度も乗らない = リソースを分散させず、伸びた 1 本に集中。
- **実装**: 候補をテキストの簡易ハッシュまたは正規化文でクラスタリングし、クラスタごとに上位 1 件だけ採用。重複引用を減らしつつ「勝ちスレ」に集中。

### 3.4 データで「何が効いたか」だけを伸ばす

- **観察**: どの「Bot っぽさ・言語・時間帯・テンプレ」の組み合わせで our_impressions / our_clicks が伸びたかは、データが答えを持つ。
- **秘策**: **ログを溜め、条件別に集計するだけ**で、次に「どこに本数を振るか」が決まる。AI は「仮説を増やす」より「観測された効き目で重みを変える」のが得意。
- **実装**: buzzweave_post_log の our_impressions / our_clicks を、言語・UTC時間帯・hype 高/低・テンプレ番号で集計。効いている条件に run 数・cap・言語スケジュールを寄せる（analyze-our-pqt-buzz.js の延長）。

### 3.5 バースト検知で「今撃つ」を増やす（オプション）

- **観察**: Bot は時間帯で波を作る。ある 5〜10 分に hype 投稿が集中すると、提灯の流入も集中する。
- **秘策**: 検索結果の **直近 N 分の hype 投稿数が閾値を超えたら「今が波」** とみなし、その run の cap を一時的に増やす or 次の run を早める。
- **実装**: 検索後に「直近 10 分の hype 含有投稿数」を数え、閾値超なら cap を 1.2〜1.5 倍にする。Cron はそのままでも「波のときは多く撃つ」だけ変える。

### 3.6 他アセットへのスケールは「キーワード＋テンプレ」の差し替え

- **観察**: 仕手Bot＋提灯の構造はクリプト以外（株・FX・コモディティ）でも同じ。
- **秘策**: プレイブックはそのまま。**検索キーワードとテンプレ本文だけアセット用に差し替え**れば、同じエンジンで他市場に展開できる。AI は「型」を変えずに語彙とメッセージを差し替えるのが得意。
- **実装**: SEARCH_KEYWORDS_BY_LANG と PQT テンプレをアセット別に切り替える設定（例: asset=crypto | equity | fx）。ロジックは共通。

---

## 4. まとめ

- **戦略**: 仕手Botの流れに乗り、同じスレで提灯に「構造・トラップ回避」＋リンクを届ける。Bot 攻略 = 提灯救済。
- **戦術**: 多く拾い多く撃つ、Bot っぽいスレを優先、reply-first、言語・時間帯合わせ、シンプル選定で本数確保。
- **AI の秘策**: （1）感情に同意してから軸をずらすコピー、（2）初動リプライを奪う新しさボーナス、（3）同一キャンペーンは 1 本だけ引用、（4）データで効いた条件に振る、（5）バースト時に cap 増、（6）他アセットはキーワード＋テンプレ差し替えでスケール。

これらは「遠慮なく Bot を利用する」前提の上に、データとパターンで精度を足していく方向になる。
