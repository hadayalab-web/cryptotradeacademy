#### 3.2 実際の実行ロジック（getPeakMapForHour）

**実装ファイル**: `services/x/optimization.js`

**実行される時間帯**:
- UTC 0:00 - AR, EN
- UTC 1:00 - KO, EN
- UTC 2:00 - EN
- UTC 4:00 - ES
- UTC 6:00 - PT-BR
- UTC 8:00 - EN, ES, PT-BR, AR, JA, KO（全言語）
- UTC 10:00 - JA
- UTC 12:00 - EN + Free Report
- UTC 13:00 - KO, JA（オフピーク）
- UTC 14:00 - EN, JA（オフピーク）+ Free Report
- UTC 15:00 - ES + Free Report
- UTC 16:00 - KO
- UTC 18:00 - AR + Free Report
- UTC 20:00 - EN, PT-BR + Minimal
- UTC 21:00 - ES, EN
- UTC 22:00 - PT-BR, ES, EN

**⚠️ 重要な発見**:

1. **言語別エンドポイントは時間帯チェックを行わない**:
   - 言語別エンドポイント（`x-quote-repost-en.js`など）は`postQuoteRepostsForLang`を直接呼び出す
   - 時間帯チェック（`getPeakMapForHour`）は行われない
   - **結果**: Cron設定通りに6-10分ごとに実行される
   - **影響**: クールダウンと日次上限により実際の投稿数は制限されるが、無駄なAPI呼び出しが発生する可能性がある

2. **`getPeakMapForHour`は使用されていない**:
   - `getPeakMapForHour`は`x-quote-repost.js`のメインエクスポート（`handler`関数）でのみ使用される
   - しかし、実際のCron設定では言語別エンドポイントが使用されている
   - **結果**: `getPeakMapForHour`の実装は現在使用されていない

3. **スケジュールの重複**:
   - UTC 13:00, 14:00, 20:00で複数のタイプ（quote + free_report/minimal）が重複
   - これは意図的な設計のようですが、ログで確認が必要

4. **オフピーク時間の設定**:
   - UTC 13:00, 14:00がオフピークとして設定されているが、Cron設定では通常通り実行される
   - ただし、`getInfluencerCountForLang`でオフピーク時間の投稿数を減らす処理が実装されている

## ⚠️ 発見された矛盾と欠陥

### 1. 言語別エンドポイントが時間帯チェックを行わない（重要）

**問題**:
- 言語別エンドポイント（`x-quote-repost-en.js`など）は`postQuoteRepostsForLang`を直接呼び出す
- 時間帯チェック（`getPeakMapForHour`）は行われない
- Cron設定通りに6-10分ごとに実行される

**影響**:
- クールダウンと日次上限により実際の投稿数は制限される
- しかし、無駄なAPI呼び出しが発生する可能性がある
- クールダウン中の実行はスキップされるが、処理時間とリソースは消費される

**実際の動作**:
- Cron設定通りに6-10分ごとに実行される
- クールダウンチェックにより、実際に投稿されるのはクールダウンが解除された時のみ
- 日次上限により、1人あたり最大4回/日の投稿が制限される

**推奨修正**:
1. 言語別エンドポイントにも時間帯チェックを追加する（`getPeakMapForHour`を使用）
2. または、Cron設定を最適化して、投稿が期待される時間帯のみ実行する
3. ただし、現在の実装でもクールダウンと日次上限により過剰な投稿は防止されている

### 2. クールダウンとスケジュールの整合性

**問題**:
- EN: 6時間クールダウン
- その他: 8時間クールダウン
- しかし、Cron設定では6-10分ごとに実行

**影響**:
- クールダウン中は投稿されないため、実際の投稿頻度は期待より低い
- ただし、これは意図的な設計（スパム回避）の可能性がある

**✅ 問題なし**: クールダウンは適切に機能しています。

### 3. インフルエンサー数の設定と実際のストック数の不一致

**設定値** (`config/influencerStrategy.js`):
- EN: 35人/回（ピーク時間）、14-16人/回（オフピーク）
- ES: 20人/回（ピーク時間）、8人/回（オフピーク）
- PT-BR: 16人/回（ピーク時間）、6-7人/回（オフピーク）
- AR: 12人/回（ピーク時間）、5人/回（オフピーク）
- JA: 10人/回（ピーク時間）、4人/回（オフピーク）
- KO: 8人/回（ピーク時間）、3人/回（オフピーク）

**実際のストック数**:
- EN: 210人
- ES: 168人
- PT-BR: 158人
- AR: 112人
- JA: 98人
- KO: 78人

**✅ 問題なし**: ストック数は設定値の2倍以上あり、十分な余裕があります。

### 4. 日次上限とクールダウンの関係

**設定**:
- 日次上限: 1人あたり最大4回/日
- クールダウン: EN 6時間、その他 8時間

**計算**:
- EN: 6時間クールダウン → 理論上最大4回/日（24時間 ÷ 6時間 = 4回）
- その他: 8時間クールダウン → 理論上最大3回/日（24時間 ÷ 8時間 = 3回）

**⚠️ 矛盾**:
- 日次上限が4回/日だが、8時間クールダウンでは実質的に3回/日が上限
- ただし、ローテーションにより平均4.3回/日を達成可能とコメントされている

**✅ 問題なし**: ローテーションにより実現可能です。
