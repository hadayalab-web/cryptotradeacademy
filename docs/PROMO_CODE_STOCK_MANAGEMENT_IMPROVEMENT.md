## ⚠️ 問題点

### 1. 在庫切れによる機会損失

**問題**:
- 50枚のクーポンがすぐに売り切れる
- 在庫切れの間、成約機会を失う
- リードが購入できない状態になる

**影響**:
- 収益機会の損失
- リードの離脱リスク
- CVRの低下

---

## 💡 改善案

### 1. クーポン枚数の増加（即座に実行可能） ✅

**方法**: Whop Dashboardで手動設定

**推奨枚数**:
- **現状**: 50枚
- **推奨**: **100-200枚**（需要に応じて調整）

**理由**:
- 48時間で約100-225成約が予測される
- 50枚では在庫切れが発生する可能性が高い
- 100-200枚に増やすことで、在庫切れを防ぐ

---

### 2. 在庫切れ時の自動通知機能（実装可能） ✅

**機能**:
- 在庫が0になったらCEOに自動通知
- 在庫が少なくなったら（10枚以下）CEOに警告通知

**実装方法**:
- `services/whop/promo-monitor.js`にCEO通知機能を追加
- 在庫が0または10枚以下になったらCEOレポートを送信

---

### 3. クーポン補充の自動化（検討中） ⚠️

**機能**:
- 在庫が少なくなったら（20枚以下）自動でクーポン枚数を増やす
- Whop APIの`updatePromoCode`を使用

**実装方法**:
```javascript
// 在庫が20枚以下になったら自動で100枚に増やす
if (remainingStock <= 20) {
  await updatePromoCode(PROMO_CODE_ID, { stock: 100 });
}
```

**注意事項**:
- Whop APIの仕様を確認する必要がある
- 自動更新が可能かどうか確認が必要

---

### 4. 複数プロモコードの運用（検討中） 💡

**機能**:
- 複数のプロモコードを用意（例: DEFEND50-1, DEFEND50-2, DEFEND50-3）
- 1つが売り切れたら、次のプロモコードに自動切り替え

**実装方法**:
- 環境変数で複数のプロモコードIDを設定
- 在庫が0になったら、次のプロモコードに切り替え
