# Grok と「X センチメント」についての注意書き

## 経緯（教訓）

- **Copilot** に X 引用リポストを推奨され、その方向で時間をかけたが、現運用は**リプライ専用**に一本化し引用リポストは廃止した。
- **「Grok が X のセンチメントを解析できる」** と言われた前提で設計してきたが、Grok は **X に直接アクセスしておらず、ライブでスキャンしているわけではない**。以下に事実と運用上の扱いをまとめる。

## 事実

- **Grok（xAI API）は LLM である**。当方から送っているのは **プロンプト** だけで、Grok はそのプロンプトに対してテキストを生成している。
- **Grok は X（Twitter）の API やタイムラインに直接アクセスしていない**。X のアルゴを「抜けて」リアルタイムで X をスキャンしているわけではない。
- したがって、`analyzeXSentimentLive` / 高解像度 X 解析が返す「X センチメント」は、
  - **Grok の学習データに基づく推論** または
  - **プロンプトに含めた文脈（例: CQ の要約や我々の記述）からの生成**
  であり、「今の X 上の実測センチメント」ではない。

## 現在の役割の整理

- **Regular / KIBA の配信ロジック**では、Grok の出力を「**ナラティブ・文言の生成用**」および「**CQ 等と組み合わせた総合判定の一要素**」として使っている。
- つまり「X をスキャンした結果」ではなく、「**我々が渡した文脈＋プロンプトに対する LLM の出力**」として扱うのが正しい。
- X アルゴを抜けているかどうかは関係なく、**Grok は X を直接見ていない**ので、「X センチメントをスキャンしている」という表現は誤解を招く。

## 運用上の扱い

- コメントやドキュメントでは「X センチメントをスキャン」ではなく、  
  **「プロンプトに基づく Grok のセンチメント風出力（ナラティブ・文言生成用）」** と明記するのがよい。
- リアルタイムの X 雰囲気が必要な部分は、**CQ オンチェーンや KIBA の 5 分データ**など、実際に取得しているデータに寄せる方が一貫している。
