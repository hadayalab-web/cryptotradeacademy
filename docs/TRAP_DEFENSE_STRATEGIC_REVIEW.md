- **現状**: 「Market Bug」と「Trap」が混在 → ブランドメッセージが分散
- **統一後**: 「Trap Defense」という一貫したブランドメッセージ
- **効果**: ユーザーの認知負荷軽減、ブランド記憶性向上

#### 1.2 **カテゴリ創造の強化** ✅

- **「Trap Defense」カテゴリ**: 既に確立されているカテゴリ
- **「Market Bug」**: カテゴリが不明確
- **統一効果**: 「Trap Defense」カテゴリへの完全な収束

#### 1.3 **ユーザー理解の向上** ✅

- **「トラップ」**: トレーダーにとって直感的で理解しやすい
- **「バグ」**: 技術的で理解しにくい
- **効果**: ユーザーエンゲージメント向上

#### 1.4 **実装上の整合性** ✅

- **既存実装**: `trapDetector.js`, `trapRiskScorer.js`が既に存在
- **統一効果**: コードベース全体の一貫性向上

**実装影響範囲**:
- `marketBugDetector.js` → `trapDetector.js`に統合またはリネーム
- `marketBug` → `trapDetection`に変数名変更
- メッセージテンプレート: 「Market Bug」→「Trap Detection」に統一

## 2. シグナル生成戦略転換の評価

### ✅✅ **極めて強く推奨（ブルーオーシャン戦略として最適）**

**理由**:

#### 2.1 **競合差別化の圧倒的優位性** ✅✅

**現状の競合**:
- 10,000+社のシグナルサービスが「BUY/SELL/LONG/SHORT」を提供
- レッドオーシャン状態

**提案後のポジショニング**:
- **「トラップ検知アラート」**: 競合が提供していない機能
- **ブルーオーシャン**: 新カテゴリ「Trap Defense」での独占的ポジショニング
- **効果**: 競合3社のみの市場（既に確立済み）

#### 2.2 **ユーザー価値の本質的向上** ✅✅

**従来のシグナル（BUY/SELL）の問題**:
- **意思決定の負担**: ユーザーが「いつエントリー/エグジットするか」を判断する必要がある
- **責任の所在**: 損失時の責任がユーザーに帰属
- **心理的負担**: FOMO/恐怖による誤判断リスク

**トラップ検知アラートの優位性**:
- **防御的アプローチ**: 「危険を回避する」という明確な価値提供
- **責任の明確化**: 「トラップを検知した」という事実提示 → ユーザーの判断をサポート
- **心理的負担軽減**: 「取引しない」という選択肢を提示

#### 2.3 **精度向上の戦略的意味** ✅✅

**現状の課題**:
- BUY/SELLシグナルの精度は80%だが、**エントリータイミング**が課題
- ユーザーが「いつエントリーするか」で結果が変わる

**トラップ検知アラートの優位性**:
- **検知精度**: 「トラップが発生している」という事実の検知 → 精度向上が容易
- **タイミング問題の回避**: 「今は取引すべきでない」という明確なメッセージ
- **80%勝率の維持**: 既存のバックテスト実績を活用可能

#### 2.4 **USP1との完全統合** ✅✅

**USP1（市場バグ検知）の本質**:
- 既に「トラップ検知」のロジックが実装済み
- `trapDetector.js`, `trapRiskScorer.js`が存在
- `marketBugDetector.js`も実質的に「トラップ検知」機能

**統合効果**:
- **USP1の明確化**: 「Market Bug Detection」→「Trap Detection」で機能が明確に
- **メッセージング統一**: 「Trap Defense」ブランドとの完全統合

## ⚠️ 実装上の注意事項

### 1. **後方互換性の維持**

**課題**: 既存の`marketBug`変数を使用しているコードが多数存在

**対策**:
- 移行期間中は`marketBug`と`trapDetection`の両方をサポート
- 段階的に`trapDetection`に移行

### 2. **シグナル生成ロジックの段階的移行**

**課題**: BUY/SELLシグナル生成ロジックが多数のファイルに分散

**対策**:
- Phase 1: トラップアラートを追加（既存シグナルは維持）
- Phase 2: トラップアラートを優先表示
- Phase 3: BUY/SELLシグナルを非表示化（オプション）

### 3. **多言語実装の品質確保**

**課題**: 6言語同時展開で翻訳品質の維持が困難

**対策**:
- ネイティブスピーカーによる翻訳レビュー
- 各言語版での機能テスト
- A/Bテストで効果測定
