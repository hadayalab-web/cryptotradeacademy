# なぜ引用リポストなのか？ リプライではダメなのか？

**問い**: ターゲット投稿への**レス（リプライ）**で届ければよいのでは？ なぜ**引用リポスト**にこだわっているのか見えなくなってきた。

---

## 1. 届け先で比べる

| 届け方 | 誰に届くか |
|--------|------------|
| **リプライ** | その投稿の**スレを開いた人**。Bot に群がった提灯はまさにここにいる。**直接届く**。 |
| **引用リポスト** | **私たちの新規ツイート**として配信される。フォロワー・アルゴで私たちの TL に載った人。**スレを開いていない人**にも届くが、すでに Bot スレにいる提灯には、そのスレ内では見えない（別オブジェクトなので）。 |

**結論**: **「Bot スレにいる提灯に届ける」だけなら、リプライのほうが直接的。**

---

## 2. 引用リポストを選んでいた理由（推測）

- **私たちのツイートが 1 本として残る** … プロフィール・タイムラインに「引用ツイート」が並ぶ。リプライは相手のツイートにぶら下がるだけなので、私たちのフィードには残りにくい。
- **アルゴで「私たちのツイート」が流れる** … 引用 = 新規ツイートなので、フォロワーや For You に載る可能性がある。リプライはスレッド内で消費されがち。
- **歴史的経緯** … 「PQT = Parasitic Quote Tweet」として引用リポスト前提で設計されていた可能性。リプライ主体で設計し直していない。

つまり、**「私たちのコンテンツを 1 本のツイートとして配信したい」**という意図なら引用は理にかなう。**「Bot スレにいる提灯に届けたい」**だけならリプライで十分。

---

## 3. どちらを主軸にするか

- **提灯救済を主目的にする** … Bot が集客した**スレ内**にいる人に届けるのが最優先なら、**リプライ主体**のほうが筋が通る。見つけてもらう = そのスレを開いた人に見てもらう、ならリプライで足りる。
- **私たちのアカウント・コンテンツを「資産」として積みたい** … 引用で 1 本 1 本をツイートとして残し、フォロワーやアルゴに流したいなら、引用にも意味がある。

**いまの目的（仕手Bot攻略 = 提灯救済）に寄せるなら、「リプライで届ける」を主にして、引用は補助（またはやめる）という選択肢はあり得る。**

---

## 4. 運用方針（採用済み）

**引用リポストは廃止。運用はリプライのみ。**

ターゲット投稿に**リプライだけ**する（buildPqt で生成した本文＋リンク、280字以内でリプライ）。引用はしない。スレ内で確実に見つけてもらう。buzzWeaveEngine の runBuzzWeaveCyclePqtOnly はリプライのみで投稿し、slotMode / usedMode は `reply_only` でログする。
