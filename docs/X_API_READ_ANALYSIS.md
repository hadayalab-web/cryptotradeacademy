# X API Read 系の整理と課金

**前提**: X API の「読み取り」はすべて **取得したリソースごとに課金**。リクエスト数やクエリ数ではなく、**返ってきた 1 件 = 1 リソース**で課金される。

---

## Read 系 一覧（取得したリソースごとに課金）

| カテゴリ | 単価 | リソースの意味 |
|----------|------|----------------|
| **投稿: 読み取り** | $0.005 / リソース | 取得したツイート（投稿）1 件 |
| **ユーザー: 読み取り** | $0.010 / リソース | 取得したユーザー 1 件（ expansions 含む） |
| DMイベント: 読み取り | $0.010 / リソース | 取得した DM イベント 1 件 |
| リスト: 読み取り | $0.005 / リソース | 取得したリスト 1 件 |
| スペース: 読み取り | $0.005 / リソース | 取得したスペース 1 件 |
| コミュニティ: 読み取り | $0.005 / リソース | 取得したコミュニティ 1 件 |
| ノート: 読み取り | $0.005 / リソース | 取得したノート 1 件 |
| フォロー/フォロワー: 読み取り | $0.010 / リソース | 取得したフォロー/フォロワー 1 件 |
| メディア: 読み取り | $0.005 / リソース | 取得したメディア 1 件 |
| 分析: 読み取り | $0.005 / リソース | 取得した分析 1 件 |
| トレンド: 読み取り | $0.010 / リソース | 取得したトレンド 1 件 |

→ **「Read」= 取得したリソース数。クエリ数・リクエスト数ではない。**

---

## リクルートDMで使っている Read

使っているのは **投稿: 読み取り** と **ユーザー: 読み取り** のみ。

- **設計**: 1 ランあたり **送信成功 10 がマスト**。403 は次の候補へ進み、**10 達成するまで試行**する。そのために **Read 1・多ページ** で候補を確保する（1 クエリで複数ページ取得）。
- **検索** `GET /2/tweets/search/recent` を 1 ランあたり 1 クエリ × **複数ページ**（`pagesPerBucket`、`maxResults: 30`）で実行。
- 1 回の検索で返るもの:
  - **data**: ツイート一覧 → **投稿: 読み取り** のリソース数 = 返ったツイート数（1 ページ最大 30 × ページ数）
  - **includes.users**: ユーザー一覧 → **ユーザー: 読み取り** のリソース数 = 返ったユーザー数（同様にページ数に比例）

### 用語の対応（混同しないように）

| 私たちの言い方 | X API の課金での意味 |
|----------------|----------------------|
| 検索ラン数 11/日（EN 6 + 他 5） | 検索**リクエスト**数。課金単位ではない。 |
| Read の課金 | **取得した投稿数** × $0.005 ＋ **取得したユーザー数** × $0.010 |

つまり「Read 11」と書くとき、それは**検索ラン数 11**の話であり、**課金上の Read（リソース数）** とは別。課金は「その 11 回の検索で合計何件の投稿・ユーザーを取得したか」で決まる。

## リクルート 1 日あたりの Read コスト（目安）

### 数字の根拠

- **「1 ランあたり 最大 30 投稿 + 最大 30 ユーザー」**  
  - ゴールから逆算した値ではない。**コードで `maxResults: 30`, `pagesPerBucket: 1` と指定している**（`api/affiliate-recruit-run.js`）ため、検索 1 リクエストあたりの取得上限が 30 件であり、その分だけ `includes.users` も返る、という意味での「最大」。
- **「約 $4.95/日（最大）」**  
  - 上記の「11 ラン × 30 リソース」を単価にかけただけ。実際の取得件数は検索ヒット数・時間帯・言語に依存するため、実測しない限り「何割になるか」は不明。

### 表（コード前提: 1 ラン 1 ページ・maxResults 30）

- 1 ラン: 検索 1 回 → **コード上の上限** 30 投稿 + 30 ユーザー
- 11 ラン/日 → 上限ベースで 約 330 投稿 + 約 330 ユーザー

| 項目 | 単価 | 最大リソース数/日（コード前提） | 最大コスト/日 |
|------|------|-------------------------------|---------------|
| 投稿: 読み取り | $0.005 | 約 330 | 約 $1.65 |
| ユーザー: 読み取り | $0.010 | 約 330 | 約 $3.30 |
| **Read 合計** | — | — | **約 $4.95**（最大） |

**補足**: 「実際は 1/2〜2/3 程度」といった割合は、本プロジェクトのログや分析に基づくものではない。実コストは実測または X の利用レポートで確認すること。

## まとめ

1. **Read 系はすべて「取得したリソースごと」**。リクエスト数・クエリ数では課金されない。
2. リクルートで課金対象になる Read は **投稿: Read** と **ユーザー: Read** のみ。
3. 検索ラン数（11/日）は「何回検索したか」の指標。課金は「その検索で取得した投稿数・ユーザー数」で計算する。
4. Read コストを抑えるには、**1 ランあたりの取得件数（maxResults / ページ数）を必要最小限にする**か、**ラン数自体を減らす**必要がある。
