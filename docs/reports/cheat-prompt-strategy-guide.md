# チートプロンプト戦略ガイド

## 🎯 概要

このドキュメントは、AI（Grok、Gemini、GPT-5.2）に対して「チート級」の戦略を引き出すためのプロンプト設計ガイドです。

## 🚀 チートプロンプトの設計方針

### 1. 安全バイアスの回避

**問題**: 多くのAIは「安全圏」を推奨し、保守的な推奨値を提示する傾向があります。

**解決策**: 
- 「安全圏」ではなく「最大限の成果」を求める
- 「推奨値」ではなく「技術的制約内での最大値」を求める
- 「リスク回避」ではなく「リスク対報酬評価」を求める

### 2. 技術的制約への焦点

**問題**: AIは技術的制約と保守的な推奨値を混同することがあります。

**解決策**:
- X APIレート制限（10,000/24hrs）などの**技術的制約**のみを考慮
- 「スパム判定リスク」などの**推測に基づく制約**を排除
- **実際のデータ**に基づいた推奨を求める

### 3. エッジケースの探索

**問題**: AIは一般的なケースに焦点を当て、エッジケースを見逃すことがあります。

**解決策**:
- アルゴリズムの「抜け道」を明示的に求める
- エッジケースと最適化機会を探る
- 「通常の方法」ではなく「最適化された方法」を求める

### 4. データ駆動アプローチ

**問題**: AIは推測に基づいた推奨を提示することがあります。

**解決策**:
- 「推測」ではなく「実際のデータ」に基づいた推奨を求める
- 「一般的な推奨」ではなく「具体的な数値」を求める
- 「可能性」ではなく「確実性」を求める

### 5. リスク評価の明確化

**問題**: AIはリスクを過大評価し、リスクを取る価値を評価しないことがあります。

**解決策**:
- リスクを明確に評価する（低/中/高）
- リスクを取る価値があるかを判断する
- 可逆的なアクションと不可逆的なアクションを区別する

## 📋 チートプロンプトの構造

### System Prompt（システムプロンプト）

```
You are an expert [DOMAIN] reverse engineer and growth hacker. 
Your mission is to identify [SPECIFIC GOAL] while staying within 
TECHNICAL limits (not conservative recommendations).

**CRITICAL INSTRUCTIONS:**
1. Ignore "safe zone" recommendations
2. Focus on TECHNICAL limits only
3. Identify algorithmic loopholes
4. Data-driven analysis
5. Maximum output within constraints
```

### User Prompt（ユーザープロンプト）

1. **コンテキストの提供**: 現在の実装と技術的制約を明確に説明
2. **具体的な質問**: 「抜け道」「エッジケース」「最大出力」を明示的に求める
3. **出力形式の指定**: 構造化された回答を求める
4. **リスク評価の要求**: リスクを明確に評価する

## 📊 期待される出力

### 1. エグゼクティブサマリー
- 特定された主要なアルゴリズムの抜け道
- 技術的制約内での最大出力戦略
- リスク対報酬評価

### 2. アルゴリズムの抜け道とエッジケース
- 活用できる特定の抜け道
- エッジケースと最適化機会

### 3. 最大出力戦略
- 最大安全投稿頻度（技術的制約内）
- 最適な投稿パターン
- コンテンツバリエーション戦略

### 4. リスク評価
- 実際のリスク（保守的な推測ではなく）
- 可逆的 vs. 不可逆的なアクション
- 積極的な戦略のリスク対報酬比率

### 5. 実装ロードマップ
- Phase 1: 即座の最適化（低リスク、高報酬）
- Phase 2: 段階的スケーリング（中リスク、高報酬）
- Phase 3: 積極的な戦略（高リスク、最大報酬）

## 🚨 注意事項

1. **技術的制約の尊重**: プラットフォームの技術的制約は尊重する
2. **段階的なテスト**: 積極的な戦略は段階的にテストする
3. **リスク管理**: リスクを明確に評価し、管理する
4. **データ検証**: AIの推奨は実際のデータで検証する
