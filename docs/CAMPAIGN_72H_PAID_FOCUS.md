# 72h 有料集中キャンペーン：修正案

**※ 以下「承認済み方針」は参謀推奨案をすべて承認したうえでの確定方針とする。**

---

## 承認済み方針（参謀推奨 → 全承認）

### 2導線のランチェスター（主・従）

| 役割 | 導線 | 割合・用途 |
|------|------|------------|
| **主** | Vidalytics → Whop（Regular） | リプ CTA の **8〜9割**。ストーリー→VSL→オファーで納得して申し込む層。主 KPI。 |
| **従** | Whop 直（Regular） | **1〜2割**。「もう話は聞いた／リンクだけ」用の短い導線。サブ KPI。 |

- 計測: Vidalytics 経由の成約を主、Whop 直の成約をサブで見る。

### 緊急性

- **主**: 「**あと〇枠**」のみで統一。時間の緊急性は原則つけない。
- **サブ**（使う場合）: 「今週の〇枠」「今月の枠はあと〇」など、**枠と時間を一体化した表現**に限る。「72h 限定」など独立した時間限定は使わない（ローリング希少性と矛盾しうるため）。

## 方針（3本柱）

1. **有料導線に絞る**
2. **ローリング希少性**（先着50名 → 完売したら追加50名を宣言して繰り返し）
3. **リプライ絶対数を増やす**

---

## 1. 有料導線に絞る

### 対象にする導線（2本のみ・主従あり）

| 役割 | 導線 | 経路 | 成果物 |
|------|------|------|--------|
| **主** | A | クリック → **Vidalytics VSL** → Whop **Regular** | 有料版（Regular Briefing） |
| **従** | B | クリック → **Whop 直** **Regular** | 有料版（Regular Briefing） |

- **Minimal（無料版）** への誘導は、キャンペーン期間中は出さない or 控えめにする。
- リプの CTA: **主（Vidalytics）を 8〜9割**、**従（Whop 直）を 1〜2割**。従は「すぐ試す用」など用途を限定。

### 実装まわりでやること

- **pqtTemplates / pqtCtaEngine**: キャンペーン用フラグ or 環境変数で「有料（Regular）のみ」に切り替え。
- リンクは **Vidalytics（Regular 着地）** と **Whop 直（Regular）** のみ使用。Minimal 用リンクは出さない。

---

## 2. ローリング希少性（先着50名 → 追加50名でループ）

- **採用理由**: 先着50名が完売しても「さらに先着50名分を追加」と宣言すれば終了で詰まらない。同じ枠を繰り返せるので運用が破綻しない。
- **「あと〇枠」**: 現在のバッチで残りが減るたびに「あと12枠」「あと3枠」と締められる。売り切れたら追加50枠でリセットするので、**「あと何枠」は永遠に使い回せる**。
- **トレードオフ**: 同じフォロワーが何度も「追加50名」を見ると「実質無制限では？」と気づくリスクはあるが、**投資対効果を優先**する方針で許容する。リプの届き先は毎回違うスレ・ユーザーが中心なので、多くの人には「今の50枠」として機能する。

### 運用

- 先着50名を宣言 → 完売（または区切りが良くなったタイミング）で「追加50名分を開放」と更新。必要に応じて繰り返す。
- 文言は「先着50名」「あと〇枠」など。追加時は「ご要望多かったため追加50名分」などで自然に繋ぐ。

### 緊急性・希少性の入れどころ（承認済み: 主＝枠のみ、時間はサブで枠と一体化）

| 場所 | 修正案 |
|------|--------|
| **リプライ本文** | 「先着50名でこのリンクは閉じる」「あと〇枠」など。**時間限定（72h等）は原則使わない**。手堅いトーンは維持。 |
| **Whop LP** | DEFEND50 の近くに「先着50名まで」を明記。追加開放時は LP 文言を更新。 |
| **Whop LP VSL** | 「Next 50 people only」→ 完売後に「We're opening 50 more spots」などに差し替え可能。※「先着50名」は入っているが「追加50枠」はコンテンツ更新が追いついていない建付けで運用OK。 |
| **Vidalytics VSL**（別導線用） | 同様に「next 50」／「50 more spots」でローリング。 |

### オファー

- **DEFEND50**（50% off）はそのまま。
- プラン: 月額 $99（1日トライアル）・3ヶ月 $237（20% off）・年額 $845（29% off）。クーポンで実質半額。

### 文言の例（リプ用）

- 「先着50名でこのリンクは閉じる。止まる→確認→条件一致で動く。」
- 追加開放後: 「追加50枠が開放された。構造だけ確認しておくと差がつく。」

## 3. リプライ絶対数を増やす

### 解像度は変えず、Run 頻度を上げる

- **現状**: `BUZZWEAVE_MIN_RUN_INTERVAL_HOURS=3` → 1日 **8 Run**（Cron も 3h 間隔）。
- **キャンペーン中**: 間隔を **1時間** に変更 → 1日 **24 Run**。理論上 **約3倍** のスキャン機会。
- 選定基準（高解像度スキャン・有力仕手Bot・impression×hype×copyFit）は **そのまま**。乗せる先の質は落とさない。

### 実装済み（環境変数で制御）

- **Cron**: `vercel.json` で **毎時 0 分**（`0 * * * *`）に変更済み。通常時は間隔 3h で実質 8 Run/日、キャンペーン時は 1h で最大 24 Run/日。
- **BUZZWEAVE_MIN_RUN_INTERVAL_HOURS**: 未設定時、`CAMPAIGN_PAID_FOCUS=true` なら **1**、それ以外は **3**（`api/buzzweave-run.js`）。
- **日次 Run 上限**: `CAMPAIGN_PAID_FOCUS=true` のとき `determineDailyRunTarget` が **24** を返す（`BUZZWEAVE_DAILY_RUN_CAMPAIGN` で上書き可）。通常時は従来どおり 6/7/8。
- **cap（1 Run あたりのリプ数）**: 現状の cap のまま。Run 回数増で総リプ数が増える。

### キャンペーン終了後

- **CAMPAIGN_PAID_FOCUS** を外す or `false` にすると、間隔 3h・日次上限 8 の挙動に戻る（Cron は毎時のまま。間隔チェックで 3h に 1 回だけ実行される）。

---

## 環境変数（キャンペーン用）

| 変数 | 効果 |
|------|------|
| **CAMPAIGN_PAID_FOCUS** | `true` or `1` で有料2導線のみ・主従比率 85/15・Run 1h・日次上限 24・希少性リプ追加を有効化。 |
| **CAMPAIGN_SLOTS_LEFT** | 数値で「あと〇枠」をリプに追加（未設定時は「先着50名でこのリンクは閉じる」）。ローリングで枠を更新するときに設定。 |
| **BUZZWEAVE_DAILY_RUN_CAMPAIGN** | キャンペーン時の日次 Run 上限（デフォルト 24）。必要なら下げて利用。 |
