# テスト優先度と戦略

## 🎯 テストの重要性

計画は完璧に確立しましたが、**実際のテストが最も重要**です。テストなしでは：
- 修正が正しく動作するかわからない

- 月間$1.8M目標達成への道筋が不明確

## 📋 テスト戦略

### Phase 1: 最重要（即座にテスト）

これらのCron Jobsは**月間$1.8M目標達成に直結**するため、最優先でテスト：

1. **`x-post-free-report`** - X無料レポート投稿
   - **影響**: 無料ユーザー獲得の主要チャネル
   - **テスト時間**: 2-3分
   - **確認**: X投稿が成功しているか

2. **`x-quote-repost`** - 引用リポスト
   - **影響**: インフルエンサー経由の拡散（12投稿/日）
   - **テスト時間**: 3-5分
   - **確認**: SyntaxErrorが解消されているか、インフルエンサー発見が成功しているか

3. **`lead-discovery`** - リード発掘
   - **影響**: 新規リード獲得（2時間ごと）
   - **テスト時間**: 5-10分
   - **確認**: Grok APIが正常に動作しているか、リード発見が成功しているか

4. **`lead-discovery/process`** - リード処理
   - **影響**: リードの自動処理とTelegram送信
   - **テスト時間**: 2-3分
   - **確認**: リード処理が成功しているか

### Phase 2: 修正確認（次にテスト）

修正したCron Jobsを確認：

5. **`weekly-report`** - 週次レポート
   - **修正内容**: ファイル書き込みエラー修正
   - **テスト時間**: 1-2分
   - **確認**: ステータスコード200、JSONレスポンスが返る

6. **`monthly-engagement-report`** - 月次エンゲージメントレポート
   - **修正内容**: ファイル書き込みエラー修正、Markdownレポート追加
   - **テスト時間**: 2-3分
   - **確認**: ステータスコード200、`markdown`フィールドが含まれている

7. **`lead-discovery/cvr-dashboard`** - CVRダッシュボード
   - **修正内容**: エクスポートエラー修正
   - **テスト時間**: 1-2分
   - **確認**: ステータスコード200、`stats`と`simulation`が含まれている

### Phase 3: その他（時間があれば）

既に正常動作しているCron Jobs：
- `vsl1-post`, `vsl2-free-users`, `vsl1-reminder`, `vsl2-last-call` など

## 🚨 問題が発生した場合

### エラーが発生したCron Job
1. **ログを詳細に確認**
   - Vercelのログ画面でエラーメッセージを確認
   - エラーの種類を特定（SyntaxError、API接続エラー、など）

2. **修正内容を確認**
   - `docs/CRON_JOBS_FIX_SUMMARY.md`を参照
   - 修正が正しくデプロイされているか確認

3. **追加修正が必要な場合**
   - エラーの原因を特定
   - 修正を実施
   - 再デプロイ
   - 再テスト
