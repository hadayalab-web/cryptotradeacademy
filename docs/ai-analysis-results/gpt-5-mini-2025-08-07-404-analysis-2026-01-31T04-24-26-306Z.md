1) 根本原因（Vercel仕様に基づく分析）
- Vercel のサーバレス関数（非-Next専用）や Next.js の API ルートは「ビルド出力に存在する関数」をデプロイします。もしプロジェクトが Next.js なら API ルートは pages/api または app/api に置く必要があります（参考: https://vercel.com/docs/concepts/functions/serverless-functions と https://vercel.com/docs/frameworks/nextjs/deployment ）。
- あなたの状況でビルドログに x-quote-repost-{lang}.js のコンパイルログが一切表示されない点は、Vercel が「そのファイルをビルド対象として認識していない」ことを示唆します。理由は主に以下：
  - buildCommand（npm run build）が src をビルドして出力ディレクトリに置き換えており、ルートの api/ ファイル群が出力に含まれていない（→ デプロイ時に見えない）。例えば Next.js の場合、Next ビルドで pages/api 内の関数だけが扱われ、プロジェクトの api/ フォルダは無視されることがあります。
  - .vercelignore や build スクリプトで意図せずファイルを除外している。
  - その関数のビルド中に依存解決／バンドルでエラーが発生し、Vercel がその関数をスキップ（結果：404）している。ビルドログに個別エラーが出ているか要確認。
- ハイフン（-）について：Vercel と Node のファイルシステム上、ハイフンが名前に含まれること自体は問題になりません。言語コード “pt-br” のようにハイフンが含まれているのは OK（ただし URL の扱いや再書き換えで注意が必要）。したがって「ファイル名にハイフンがあることが直接の原因」という可能性は低いです（例外：あなたの build スクリプトでハイフンをファイル名変換ルールにしている場合は別）。
- functions セクションについて：vercel.json の functions セクションは「関数ごとの設定（メモリ／タイムアウト／includeFiles 等）」を与えますが、ここに未記載だからといって自動検出が無効になる、とは通常はなりません。ただし以前 functions セクションを使って限定的に includeFiles を設定していると、意図せず依存が見つからずビルドに失敗するケースがあります。公式: https://vercel.com/docs/project-configuration#functions
