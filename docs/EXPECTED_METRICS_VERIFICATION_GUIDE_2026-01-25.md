# 期待値検証ガイド（2026-01-25）

## 📋 概要

このドキュメントは、「Cursor/Composer 1病」対策として、AIが提示した期待値が実際に達成されているかを検証する方法を説明します。

## 🎯 目的

1. **期待値と実際の値の自動比較**
2. **差異の根本原因分析**
3. **早期警告システム**
4. **継続的な改善**

## 🔍 検証方法

### 1. 24時間後の検証（手動）

```bash
# 期待値検証スクリプトを実行
python scripts/verify_expected_metrics_24h.py \
  --start-date 2026-01-25 \
  --end-date 2026-01-26 \
  --log-file data/vercel-logs/logs_result.json \
  --output docs/verification_report_2026-01-26.json
```

**期待される出力**:
- ✅ OK: 期待値の範囲内
- 🔴 大幅に未達: 期待値を大幅に下回る
- 🟢 大幅に超過: 期待値を大幅に上回る

### 2. リアルタイムモニタリング（自動）


**実行タイミング**:
- 毎時間実行（Cron Job）
- または、手動で実行

## 🔍 差異の根本原因分析

### インプレッションが大幅に下回る場合

**考えられる原因**:
1. Cron Jobsの実行失敗
2. インフルエンサーのパフォーマンス低下
3. X APIのレート制限
4. 市場状況の変化（予測外の低エンゲージメント）

**確認方法**:
```bash
# 1. Cron Jobsの実行ログを確認
python scripts/check_all_cron_jobs_from_logs.py

# 2. X APIのエラーログを確認
grep -i "error\|400\|429" data/vercel-logs/logs_result.json

# 3. インフルエンサーのパフォーマンスを確認
# （Vercel KVからインフルエンサーストックを取得）
```

### コンバージョンが大幅に下回る場合

**考えられる原因**:
1. UTMパラメータの設定ミス
2. Whopトラフィックの減少
3. コンテンツ品質の問題
4. 市場センチメントの変化

**確認方法**:
```bash
# 1. UTMパラメータを確認
grep -i "utm" api/x-post-free-report.js

# 2. Whopトラフィックを確認
# （Whop APIから実際のトラフィック数を取得）

# 3. コンテンツ品質を確認
# （Grok APIのレスポンスを確認）
```

## 📈 継続的な改善

### 1. 期待値の見直し

毎週、以下のデータを分析し、期待値を更新：

- 過去7日間の実際のメトリクス
- 市場状況の変化
- インフルエンサーのパフォーマンス

### 2. 許容誤差の調整

実際のデータに基づいて、許容誤差を調整：

- 変動が大きいメトリクス: 許容誤差を拡大
- 変動が小さいメトリクス: 許容誤差を縮小

### 3. 根本原因の対策

差異の根本原因を特定し、対策を実施：

- Cron Jobsの実行失敗 → エラーハンドリングの改善
- APIエラー → リトライロジックの追加
- インフルエンサーのパフォーマンス低下 → インフルエンサーの見直し
