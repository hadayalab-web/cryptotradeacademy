## 🎯 基本設計

### ✅ **COOがWhop API経由で制御（基本原則）**

**核心**: Whop APIは単なるデータソースではなく、**COOがすべてのオペレーションを制御するための制御レイヤー**です。

```
┌─────────────────────────────────────────┐
│          Whop（基本・中核）              │
├─────────────────────────────────────────┤
│ ・プロダクト管理                         │
│ ・アフィリエイター管理                   │
│ ・アフィリエイトリンク生成               │
│ ・コミッション追跡                       │
│ ・パフォーマンス分析                     │
└─────────────────────────────────────────┘
           ↑
           │ 補強・導線
           │
┌─────────────────────────────────────────┐
│   外部ワークフロー（補強）               │
├─────────────────────────────────────────┤
│ ・アフィリエイタースカウト自動化         │
│ ・候補検索（Grok/GPT/Gemini）           │
│ ・候補分析                               │
│ ・DM送信                                 │
│ ・最終的にWhopでアフィリエイター登録     │
└─────────────────────────────────────────┘
```

### 2. **外部ワークフロー（補強・導線）**

#### `workflows/affiliate-recruitment`の役割
- ✅ **アフィリエイタースカウト自動化**
  - 候補検索（Grok/GPT/Gemini）

  - **最終的にWhopでアフィリエイター登録**

#### LPの種類
- ✅ **ユーザー向けLP**: Whopプロダクトページ


## 📋 実装方針

### 1. **Whop統合の重要性**

- ✅ **Whop統合は必須**
  - プロダクト管理: Whop
  - アフィリエイター管理: Whop
  - アフィリエイトリンク生成: Whop API
  - コミッション追跡: Whop

### 2. **外部ワークフローの役割**

- ✅ **補強・導線として機能**
  - アフィリエイタースカウト自動化
  - 候補検索・分析
  - DM送信
  - **最終的にWhopでアフィリエイター登録**

### 3. **データ管理（二重構造を解消）**

- ✅ **Whop API**: アフィリエイター情報の取得・リンク生成（管理はWhop）
- ✅ **データベース**: WhopアフィリエイターIDと候補IDの紐付け（Whopの補完）
- ✅ **CSV/JSON**: Whopダッシュボードへのインポート用のみ
- ❌ **削除**: CSV/JSONベースのデータ管理（Whopと重複）
