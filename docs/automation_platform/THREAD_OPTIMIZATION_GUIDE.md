# 🚀 スレッドレスポンス最適化ガイド

**目的**: チャットスレッドの応答速度を向上させる  
**作成日**: 2026-01-15

---

## 🔍 スレッドが重い原因

1. **会話履歴が長すぎる** - 過去の会話がすべてコンテキストに含まれる
2. **ファイル読み込みが多い** - 毎回多くのファイルを読み込んでいる
3. **コードベース検索が多い** - 広範囲の検索を実行している
4. **不要な情報がコンテキストに含まれる** - 関連性の低い情報まで読み込む

---

## ✅ 対策

### 1. サマリードキュメントを活用

**新しいチャットを開始する際:**
```
docs/CURRENT_STATUS_SUMMARY_2026-01-15.md を読んで、現在の状態を把握してから作業を開始してください
```

**効果**: 会話履歴を読み込む必要がなくなる

---

### 2. ファイル読み込みを最小限に

**推奨:**
- 必要なファイルだけを読み込む
- 一度に複数のファイルを読み込む場合は、関連性の高いものだけ

**非推奨:**
- 広範囲のファイル検索
- 不要なファイルの読み込み

---

### 3. コードベース検索を限定

**推奨:**
- 特定のディレクトリに限定（`target_directories`を使用）
- 具体的な質問をする

**非推奨:**
- 全ディレクトリを対象にした検索
- 曖昧な質問

---

### 4. 会話履歴の整理

**推奨:**
- 重要な情報はサマリードキュメントに記録
- 新しいチャットで作業を開始する場合は、サマリーを参照

**非推奨:**
- 長い会話履歴をそのまま引き継ぐ

---

## 📋 最適化された作業フロー

### 新しいチャットで作業を開始する場合

1. **サマリーを読み込む**
   ```
   docs/CURRENT_STATUS_SUMMARY_2026-01-15.md を読んで
   ```

2. **必要な情報だけを取得**
   - 特定のファイルパスが分かっている場合は直接読み込む
   - 不明な場合は、限定された検索を実行

3. **作業完了後、サマリーを更新**
   - 新しい情報をサマリーに追加
   - 完了したタスクを記録

---

## 🎯 実践例

### ❌ 非効率的な例

```
「Whopプロダクト情報を確認して」
→ 全ディレクトリを検索
→ 複数のファイルを読み込み
→ 会話履歴も含めて処理
→ レスポンスが遅い
```

### ✅ 効率的な例

```
「docs/CURRENT_STATUS_SUMMARY_2026-01-15.md を読んで、Whopプロダクト情報を確認して」
→ サマリーを読み込む（軽量）
→ スクリプトパスが分かっているので直接実行
→ レスポンスが速い
```
