# 関数呼び出し機能実装

## 概要

Gemini APIの関数呼び出し機能をMCPサーバーに追加しました。これにより、モデルを外部ツールやAPIに接続し、エージェント機能を実現できます。

## 追加された機能

### ✅ 関数呼び出し (`gemini_function_calling`)

**機能**: 外部ツールやAPIへの接続によるエージェント機能

- **ドキュメント**: https://ai.google.dev/gemini-api/docs/function-calling
- **主な用途**:
  - **知識の拡張**: データベース、API、ナレッジベースから情報にアクセス
  - **機能の拡張**: 外部ツールを使用して計算を実行（電卓、グラフ作成など）
  - **アクションを実行**: APIを使用して外部システムとやり取り（予約のスケジュール設定、メール送信など）

## 対応モデル

以下のモデルが関数呼び出しをサポートしています：

- ✅ Gemini 3 Pro プレビュー
- ✅ Gemini 3 Flash プレビュー
- ✅ Gemini 2.5 Pro
- ✅ Gemini 2.5 Flash（デフォルト）
- ✅ Gemini 2.5 Flash-Lite
- ✅ Gemini 2.0 Flash

## 関数呼び出しの種類

- **関数呼び出し**: 基本的な関数呼び出し
- **並列関数呼び出し**: 複数の関数を並列で呼び出し
- **コンポジション関数呼び出し**: 関数の連鎖的な呼び出し

## 使用例

### 会議のスケジュール設定

```javascript
{
  "model": "gemini-2.5-flash",
  "prompt": "来週の月曜日の午後3時に、JohnとMaryとの会議をスケジュールしてください",
  "functions": [
    {
      "name": "schedule_meeting",
      "description": "指定された参加者との会議を指定された日時でスケジュールします",
      "parameters": {
        "type": "object",
        "properties": {
          "attendees": {
            "type": "array",
            "items": {"type": "string"},
            "description": "会議に参加する人のリスト"
          },
          "date": {
            "type": "string",
            "description": "会議の日付（例: '2024-07-29'）"
          },
          "time": {
            "type": "string",
            "description": "会議の時間（例: '15:00'）"
          },
          "topic": {
            "type": "string",
            "description": "会議のトピック"
          }
        },
        "required": ["attendees", "date", "time"]
      }
    }
  ]
}
```

### 天気予報の取得

```javascript
{
  "model": "gemini-2.5-flash",
  "prompt": "東京の今日の天気を教えてください",
  "functions": [
    {
      "name": "get_weather",
      "description": "指定された都市の天気予報を取得します",
      "parameters": {
        "type": "object",
        "properties": {
          "location": {
            "type": "string",
            "description": "都市名"
          },
          "date": {
            "type": "string",
            "description": "日付（オプション、デフォルト: 今日）"
          }
        },
        "required": ["location"]
      }
    }
  ],
  "functionResults": {
    "get_weather": {
      "temperature": 25,
      "condition": "晴れ",
      "humidity": 60
    }
  }
}
```

### 複数の関数呼び出し

```javascript
{
  "model": "gemini-2.5-pro",
  "prompt": "東京の天気を確認して、それに基づいて適切な服装を提案してください",
  "functions": [
    {
      "name": "get_weather",
      "description": "天気予報を取得します",
      "parameters": {
        "type": "object",
        "properties": {
          "location": {"type": "string"}
        },
        "required": ["location"]
      }
    },
    {
      "name": "recommend_clothing",
      "description": "天気に基づいて服装を提案します",
      "parameters": {
        "type": "object",
        "properties": {
          "temperature": {"type": "number"},
          "condition": {"type": "string"}
        },
        "required": ["temperature", "condition"]
      }
    }
  ]
}
```

## 関数呼び出しの連鎖

関数呼び出し機能は、最大5回（デフォルト）まで反復的に関数を呼び出すことができます：

1. モデルが関数呼び出しを生成
2. 呼び出し側が関数を実行
3. 結果を`functionResults`パラメータで提供
4. モデルが結果を受け取り、次の関数呼び出しまたは最終回答を生成

## ベストプラクティス

### 1. 関数とパラメータの説明

説明は、非常に明確かつ具体的に記述します。モデルは、この説明に基づいて正しい関数を選択し、適切な引数を指定します。

### 2. 命名

わかりやすい関数名を使用します（スペース、ピリオド、ダッシュは使用しません）。

### 3. 強い型指定

パラメータに特定の型（整数、文字列、列挙型）を使用して、エラーを減らします。有効な値のセットが限られている場合は、列挙型を使用します。

### 4. ツールの選択

モデルでは任意の数のツールを使用できますが、ツールが多すぎると、誤ったツールや最適でないツールが選択されるリスクが高まります。最良の結果を得るには、コンテキストやタスクに関連するツールのみを提供することを目指します。理想的には、アクティブなセットを最大10～20個に保ちます。

### 5. プロンプトエンジニアリング

- **コンテキストを提供**: モデルに役割を伝えます（例: 「あなたは役に立つ天気アシスタントです。」）
- **指示を与える**: 関数をいつ、どのように使用するかを指定します
- **明確化を促す**: 必要に応じて明確化を求める質問をするようモデルに指示します

### 6. 温度設定

- **Gemini 2.5以下**: 低温（例: 0）に設定して、より確定的で信頼性の高い関数呼び出しを実現
- **Gemini 3**: `temperature`をデフォルト値の1.0に維持することを強く推奨（1.0未満に設定すると、予期しない動作が発生する可能性があります）

### 7. 検証

関数呼び出しが重大な結果をもたらす場合（注文など）、それを実行する前にユーザーにその呼び出しの妥当性を確認してください。

### 8. 終了理由の確認

モデルのレスポンスで`finishReason`を常に確認し、モデルが有効な関数呼び出しを生成できなかったケースを処理します。

### 9. エラー処理

関数で堅牢なエラー処理を実装して、予期しない入力やAPIの障害を適切に処理します。モデルがユーザーに役立つ回答を生成するために使用できる、有益なエラーメッセージを返します。

### 10. セキュリティ

外部APIを呼び出す際は、セキュリティに注意してください。適切な認証と認可のメカニズムを使用します。関数呼び出しで機密データを公開しないようにします。

## 構造化出力と関数呼び出しの違い

| 機能 | 主なユースケース |
|------|----------------|
| **構造化出力** | **ユーザーへの最終的な回答の書式設定**。モデルの_回答_を特定の形式にする場合（ドキュメントからデータを抽出してデータベースに保存するなど）に使用 |
| **関数呼び出し** | **会話中にアクションを実行する**。モデルがタスクの実行を_ユーザーに依頼する_必要がある場合（たとえば、「現在の天気を取得」）を実行してから、最終的な回答を提供 |

## 制限事項

- OpenAPIスキーマのサブセットのみがサポートされています
- 関数の説明とパラメータは、入力トークンの上限にカウントされます
- トークンの上限に達した場合は、関数の数や説明の長さを制限したり、複雑なタスクをより小さな、より集約された関数セットに分割したりすることを検討してください
