# Gemini 戦略構築用プロンプト（CSO 発）

プロンプトの解像度が、得られる戦略の粒度と実行後の成果に直結する。以下をそのまま Gemini に渡し、**言語別の抽出・時間帯・コピー・Cron 設計**について実行可能な戦略を引き出す。

---

## 役割の指定

```
あなたは、当社の「X 上で仕手Botの煽り投稿に寄生し、CTA 付きリプライでトレーダーを導線に乗せる」施策の**戦略責任者（CSO）**として回答してください。多言語パフォーマンスマーケティングと、プラットフォーム（X API）制約を踏まえた設計ができる人です。曖昧な一般論ではなく、**数値・表・優先順位・Phase 分け**で答え、実装チームがそのままタスクに落とし込めるレベルで書いてください。
```

---

## コンテキスト（必ず渡す）

```
【施策の目的】
- 仕手Botの煽り投稿にリプライで寄生し、そのスレに群がるトレーダーに CTA をクリックさせる。
- 成功指標は「リプライを刺す数」だけでなく、**インプレッションの最大化**と**CTA クリック→成約**。北極星は 100 成約/日。

【現状の技術前提】
- 1 本の Cron が 30 分ごとに /api/buzzweave-run を叩く。API 内で UTC 時間から「この Run の言語」を 1 つ決めている（STRATEGIC_UTC_TO_LANG）。
- 検索: X Search API（tweets/search/recent）、lang:xx、-is:retweet、-is:reply。言語別キーワードと 30 分窓（低ボリューム言語は 60 分窓あり）。
- 候補選定: 品質フィルタ → 中央値フィルタ → クラスタ/危険度分類 → インプレ×hype×copyFit でスロット選定 → cap までリプライ投稿。
- 言語: en, es, pt, ja, ko, ar の 6 つ。現在の日次配分（share_ratio）は en 40%, es 20%, pt 15%, ar 10%, ko 8%, ja 7%。48 Run/日をこの比率で UTC 時間帯にマッピングしている。

【観測事実】
- 仕手系Botの煽り投稿は全言語圏で非常に多いが、**同一ロジックで全言語を扱うと抽出が粗い**（例: ar は 30 分で 9 件しか取れず、実際の Bot 量と乖離しているという報告あり）。
- 言語ごとに「どのキーワードでヒットするか」「いつスレが盛り上がるか」「どのトーンのコピーが刺さるか」が違う。解像度を上げるには**言語別の抽出・時間帯・コピー設計**が必要。
- 方針: **Cron も言語別に分け**、各言語で「いつ・何回 Run するか」を独立して設計する。

【制約】
- 実行環境は Vercel（Cron 本数はおおよそ 20 前後まで）。API は 1 本（/api/buzzweave-run?lang=xx）で、lang を渡して言語を指定する想定。
- X API のレート制限と、1 Run あたりの処理時間（数十秒〜数分）を超えないこと。
```

---

## 依頼（出力形式を指定する）

```
以下 1〜5 について、**表または番号付きリスト**で具体的に書いてください。可能なら「Phase 1 でやること / Phase 2 でやること」に分け、**まず手を付けるべき 3 つ**を明示してください。

1. **言語別の抽出ロジック**
   - 6 言語それぞれについて、推奨する「検索キーワードの追加・除外」「時間窓（分）」「品質フィルタの緩め方（あれば）」「スコア重みの調整方針」を表にまとめる。
   - 「データが少ないのに Bot は多い」言語（例: ar）で、ヒット数を増やすための仮説 2〜3 個と、それぞれの検証方法（何を変えて何を測るか）。

2. **言語別の時間帯設計**
   - 各言語の「トレーダーがスレに集まりやすく、CTA が刺さりやすい」現地時間帯（または UTC 帯）を 1〜2 個、根拠（例: 市場開場・就業後・宗教的休日以外のアクティブ時間）とともに示す。
   - Cron を言語別に分ける場合、**各言語の Run を「UTC 何時〜何時」に何回/日配置するか**を表で示す。48 Run/日を 6 言語でどう配分するか、または言語ごとに Run 数目標を変える場合の推奨配分。

3. **コピー・CTA の言語別チューニング**
   - 各言語で「煽りへの同意」「希少性・緊急性」「リスク注意・NFA」のどれを強く出すとクリックに繋がりやすいか、仮説を表でまとめる。
   - テンプレの「長さ・トーン・フックの種類」について、言語別に優先して A/B 検証すべき軸を 1〜2 個ずつ示す。

4. **Cron 設計（Vercel 想定）**
   - 言語別 Cron にする場合、**cron 式または「何分ごと・どの言語を固定で呼ぶか」**を 6 行の表で示す。例: en は 0,30 分に ?lang=en、ar は 8,38 分に ?lang=ar、など。Vercel の Cron 本数制限内に収めること。

5. **ロールアウトと測定**
   - 言語別ロジックを段階的に入れる場合、**まずどの 1 言語でパイロットし、何を測ってから他言語に広げるか**（指標・閾値・期間）。
   - 戦略を見直すタイミング（例: 週次で言語別インプレ・CTR を確認し、2 週間で抽出パラメータを 1 回調整する）を簡潔に書く。
```

---

## 使い方

1. 上記 **役割** → **コンテキスト** → **依頼** を順にコピーし、1 つのメッセージとして Gemini に送る。
2. 必要なら、直近のログサマリ（例: en 382 件/30 分・30 投稿、ar 9 件/30 分・3 投稿）をコンテキストの末尾に追記する。
3. 返答を `docs/` に保存し、Phase 1 のタスクを issue や TODO に落とす。
