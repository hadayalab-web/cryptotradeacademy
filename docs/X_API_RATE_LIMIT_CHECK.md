## 🔍 使用するX APIエンドポイント

### 1. POST `/2/tweets` - ツイート投稿
**用途**: VSL1投稿、無料版X投稿、無料版レポートX投稿

**レート制限**:
- **Per User (OAuth 1.0a/2.0)**: 100回/15分
- **Per App (Bearer Token)**: 10,000回/24時間

### 2. POST `/2/users/:id/retweets` - リツイート
**用途**: 引用リポスト（Quote Repost）

**レート制限**:
- **Per User**: 50回/15分

### 3. GET `/2/tweets/:id` - ツイート読み取り
**用途**: 投稿確認、引用元ツイートの取得

**レート制限**:
- **Per User**: 900回/15分
- **Per App**: 450回/15分

## ⚠️ 注意事項

### 1. 引用リポストのレート制限
- **POST `/2/users/:id/retweets`**: 50回/15分
- 引用リポストが1日あたり1,440回（240回×6言語）実行される場合、15分あたり約15回
- **通常運用時**: ✅ 制限内（30%使用）
- **ピーク時**: ⚠️ 制限超過の可能性あり（集中時）

### 2. 時間帯チェックの効果
- 既に実装されている時間帯チェックにより、投稿が分散されます
- ピーク時間帯以外の実行はスキップされるため、レート制限に引っかかる可能性は低いです

### 3. エラーハンドリング
- 429エラー（Rate Limit Exceeded）が発生した場合のリトライロジックが必要です
- `x-rate-limit-reset`ヘッダーを確認して、適切な待機時間を設定する必要があります

## 🎯 推奨事項

### 1. レート制限監視の実装
- レスポンスヘッダーの`x-rate-limit-remaining`を監視
- 残り回数が少なくなった場合のアラート設定

### 2. エラーハンドリングの強化
- 429エラー発生時の指数バックオフ実装
- `x-rate-limit-reset`に基づく待機時間の設定

### 3. 投稿の分散化
- 時間帯チェックを継続（既に実装済み）
- 引用リポストの実行間隔を調整（必要に応じて）

### 4. 使用量の追跡
- X API開発者コンソールでリアルタイム監視
- レート制限の使用率を定期的に確認

## 📋 まとめ

### ✅ 通常運用時は問題なし

- **POST `/2/tweets`**: 15-28回/15分（制限: 100回/15分）→ ✅ 制限内
- **POST `/2/users/:id/retweets`**: 15-28回/15分（制限: 50回/15分）→ ✅ 制限内
- **24時間あたり**: 1,452-2,700回（制限: 10,000回/24時間）→ ✅ 制限内

### ⚠️ 注意が必要なケース

- **引用リポストが集中する場合**: POST `/2/users/:id/retweets`の制限（50回/15分）に近づく可能性
- **時間帯チェックが機能しない場合**: 投稿が集中してレート制限に引っかかる可能性

### 🎯 結論

**現在の実装では、レート制限に引っかかる可能性は低いです。**

理由：
1. 時間帯チェックにより投稿が分散されている
2. 15分あたりの使用量が制限の30-56%程度
3. 24時間あたりの使用量が制限の14.5-27%程度

ただし、引用リポストが集中する場合は注意が必要です。レート制限監視とエラーハンドリングの実装を推奨します。
